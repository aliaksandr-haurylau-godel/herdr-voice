# AC_21 — Context: bias recognition with what the agent is talking about

Input: GitHub issue 21, `gh issue view 21`, no comments. `docs/design.md` section 4
(context) and section 7 (configuration), `docs/evidence.md` (including
"Recognition, by hand on macOS", landed with issue #13), `docs/decisions.md`, the
prototype in `spike/context.sh` and `spike/spike.sh`, and the recognition code
issue #13 shipped: `src/stt.rs`, `src/stt/command.rs`.

## as-is

No production code assembles a bias string. `src/` has capture (`src/audio.rs`,
`src/capture.rs`), the daemon, transport, config, doctor, and — since issue #13
landed and closed — recognition: `src/stt.rs` defines an `Engine` trait with one
method, `fn transcribe(&self, audio: &Path) -> Result<String, EngineError>`
(`src/stt.rs:16-18`), and `src/stt/command.rs` implements it for `[stt] engine =
"command"`, running a user-configured argument list against the take's file
(`src/stt/command.rs:107-152`). There is also one file named `src/context.rs` — but
that module parses the invocation context herdr passes per request
(`HERDR_PLUGIN_CONTEXT_JSON`, pane and tab identifiers, `src/context.rs:1`), which
is a different concern from the bias-string "context" this issue is about. A
module built for this issue needs a name that does not collide with it.

`Engine::transcribe` takes only the audio path. Nothing in the trait, in
`CommandEngine`, or in `stt::resolve` carries a bias string today. `CommandEngine`
is built once, at daemon start, from `[stt] command`, the resolved model path and
the configured language (`src/stt.rs:118-130`, `src/stt/command.rs:44-53`) — the
same "configuration is read once at daemon start" decision recorded in
`docs/decisions.md` for capture. `render()` substitutes `{audio}`, `{model}` and
`{language}` into the argument list per take (`src/stt/command.rs:16-31`); there
is no `{prompt}` or equivalent placeholder, and a bias string, unlike the model and
the language, is not known until the take's target pane is known — it cannot be
baked in at construction the way they are.

`src/config.rs` has no `[context]` table. `docs/design.md` section 7 documents the
intended keys — `conversation_turns = 6`, `file_names = 40`, `prompt_chars = 600`
(`docs/design.md:230-232`) — but they exist only as documentation; nothing reads
them.

`docs/design.md` section 4, "Context" (`docs/design.md:121-134`), already states
that context is assembled from the last turns of the target agent's conversation
(machine turns filtered), recently touched file and directory names from the
repository root, and the branch/title/agent kind — and says the pane's visible
screen is deliberately *not* the main source because it is mostly frame. This
issue's decision — that the pane, read through herdr, is a second, configurable
source used when no transcript file exists — extends that section; it is not
contradicted by anything already built, because nothing is built yet.

`spike/context.sh` is the only place this behaviour exists, unmeasured against
production code because there is none yet:

- `CTX_FILES` is built from `git status --porcelain` plus `git log -30
  --name-only`, run at the repository root (not the pane's working directory),
  split into path components rather than basenames, de-duplicated, and capped at
  `CTX_FILES_MAX` (`spike/context.sh:57-62`).
- `CTX_CONV` reads the target agent's transcript, filtered to `user`/`assistant`
  turns whose text does not start with `<task-notification>`, `<system-reminder>`,
  `<cross-session-message>`, `<local-command>` or `<command-name>`, and keeps the
  last `CTX_CONV_MSGS` (`spike/context.sh:98-108`).
- The transcript file is found two ways: first by the session id herdr reports,
  searching `~/.claude/projects/*/<id>.jsonl`; if that id is absent, stale, or
  names a file that does not exist, by the newest `.jsonl` in a project directory
  derived by slugifying the working directory and walking up to the first
  directory that exists (`spike/context.sh:73-96`, and the comment at
  `spike/context.sh:74-76` records that the id "changes while a session runs and
  may name a session whose file does not exist yet").
- `CTX_HOTWORDS` — the string the spike actually passes to whisper's `--prompt`
  (`spike/spike.sh:449`, `spike/spike.sh:526`, `spike/spike.sh:568`) — is built
  from agent kind, pane title, branch and `CTX_FILES` only, capped at
  `CTX_HOTWORDS_MAX` characters (`spike/context.sh:113-114`). `CTX_CONV` is passed
  separately, to the rewrite stage's prompt (`spike/spike.sh:299-320`), not to
  whisper.
- The pane's screen buffer (`CTX_BUF`) is collected
  (`spike/context.sh:42-45`) and reported (`spike/context.sh:132-134`) but is not
  part of either `CTX_HOTWORDS` or the rewrite prompt in the current spike.

Measurements behind this:

- "Context and its effect on the transcript" (`docs/evidence.md:22-36`): a bias
  string that contains a term restores it in the transcript; the earlier reading
  that biasing does nothing held only because the term — a directory name — was
  missing from a basename-only file list.
- "Pane screen versus conversation transcript" (`docs/evidence.md:62-66`): the
  pane screen alone is too thin to use as the main source — 80 lines reduced to
  59 characters after dropping lines with no letters or digits, against roughly
  2.6 KB for six conversation turns.
- "Prompt size limit" (`docs/evidence.md:55-61`): whisper.cpp's `--prompt` holds
  on the order of 224 tokens; an uncapped file list ran to 7277 characters,
  alphabetically ordered, which is noise past the limit.
- "Recognition, by hand on macOS" (`docs/evidence.md:383-421`): one 70-second
  take of Russian speech containing English terms, run through the built
  `command` engine (`whisper-cli` against `ggml-large-v3-turbo.bin`, `language =
  "ru"`), came back as "пули квест" with `-l ru` and no bias prompt, "пули квест"
  again with `-l auto` and no bias prompt, and **"pull request"** with `-l ru` and
  `--prompt` naming the terms — recognition cost 1.53 to 1.81 seconds across the
  three runs. The section states plainly that this narrows the earlier
  conclusion: biasing does restore terms, when the term is in the string, and the
  chain cannot produce a usable transcript for this kind of speech until context
  is collected and passed.

The `command` engine now built (`src/stt.rs`, `src/stt/command.rs`) is what ran
that take — but it ran with a bias prompt supplied by hand on the command line,
not by anything in `src/`. The engine's own interface has no place for one: see
the `Engine::transcribe` signature and `CommandEngine`'s construction, above. This
issue produces the capped bias string; whether and how it is threaded into
`Engine::transcribe` is addressed in AC-6 and the open questions below.

## to-be

Before a take is handed to recognition, the daemon can assemble a capped bias
string for the take's target pane: recently touched file and directory names from
the pane's repository, and recent conversation content for the pane's agent, drawn
from whichever of two sources — the agent's transcript file on disk, or the pane's
contents read through herdr — the configuration selects, with service turns
filtered out of whichever source is used. The string is capped in characters and
is available in a form a later change can hand to `Engine::transcribe` as its
priming input — the `command` engine that would consume it is already built.
Nothing beyond what the prototype already does is added on top for privacy: no
redaction, no scrubbing, no separate storage of what was collected once the take
that used it is done.

## Requirements

Asked for by the issue:

- R1 The bias string biases recognition with terms the person is likely to say,
  built from the pane the take belongs to.
- R2 The bias string is capped before being handed to recognition.
- R3 Two sources for the conversation content, chosen by configuration rather than
  assumed: the agent's transcript file on disk, and the pane's contents read
  through herdr.
- R4 File names are collected newest-first from the repository root, with path
  components, not basenames alone.
- R5 Service turns — `<task-notification>`, `<system-reminder>`,
  `<cross-session-message>`, command wrappers — are filtered out of conversation
  content before it reaches the bias string.
- R6 The three configuration keys already named in `docs/design.md` section 7
  (`conversation_turns`, `file_names`, `prompt_chars`) exist with their documented
  defaults, and an absent configuration file is a valid state (`CLAUDE.md`, "Rules
  for the code").
- R7 What happens when no conversation can be found at all — not just "which agent
  it is" — is a defined, non-silent outcome, per the issue's "Context" section.

Implied, and in scope only as far as R1 to R7 need it:

- R8 A module distinct from `src/context.rs`, which already owns the unrelated
  invocation-context concern; this issue's context module needs its own name.
- R9 No panic paths on the context-assembly path (`CLAUDE.md`, "Rules for the
  code"), and a testable interface — a fake transcript file, a fake pane-read
  result — since neither a microphone nor a live herdr is available to a test
  (`CLAUDE.md`, "Testing").

## Chosen readings

1. **What this issue delivers, now that the `command` engine exists.** The
   issue's Goal describes the string being "passed to the engine", and issue #13
   has since landed `Engine::transcribe(&self, audio: &Path)` and `CommandEngine`.
   Read narrowly all the same: this issue builds and exposes the capped bias
   string; wiring it into `Engine::transcribe` is left to a later change. The
   reason is not that the engine is missing — it is not — but that the trait's
   only method has no parameter for a bias string, and `CommandEngine` bakes the
   model and the language in at construction, once per daemon start
   (`src/stt.rs:118-130`), while a bias string is per-take: it depends on the
   target pane and cannot be known until the take begins. Extending the trait
   signature, or finding another channel, changes an interface issue #13 already
   shipped and is a decision this stage should not make silently. AC-6 states the
   boundary this way; anything past it is out of scope / noticed, and the shape
   of the eventual wiring is left as an open question for design, below.
2. **Whether conversation content and file names are one string or two.**
   `docs/design.md` section 4 already lists conversation, file names, branch,
   title and agent kind together under one "Context" heading, without separating
   them into a whisper-only string and a rewrite-only string the way the spike
   currently does (`CTX_HOTWORDS` versus `CTX_CONV`, see as-is). Since the
   rewrite stage is explicitly out of bounds for this issue, and the design
   document already treats context as one assembled thing, the acceptance
   criteria below treat conversation content and file names as components of one
   bias string, capped together at `prompt_chars`. Whether they are literally
   concatenated into a single string in code, or kept as two fields exposed
   together, is left to design.

## Acceptance criteria

- **AC-1** For a take whose target pane is running the one proven agent (the
  transcript-reading path measured in `docs/evidence.md`), and whose transcript
  file can be located, the bias string includes text drawn from up to
  `conversation_turns` (config, default 6) of that agent's most recent
  user/assistant turns.
- **AC-2** Turns whose text begins with `<task-notification>`, `<system-reminder>`,
  `<cross-session-message>`, or a command wrapper are excluded from both the count
  and the content in AC-1.
- **AC-3** Which source feeds the conversation component of the bias string — the
  transcript file on disk, or the pane's contents read through herdr — is set by
  configuration, not hard-wired to the file. Selecting the pane-contents source
  substitutes recent pane text for the transcript-turn text used in AC-1, for a
  pane whose agent has no readable transcript.
- **AC-4** The bias string includes recently touched file and directory names for
  the target pane's repository, collected newest-first from the repository root
  (not the pane's own working subdirectory when that differs), with intermediate
  path components included rather than basenames alone, up to `file_names`
  (config, default 40) entries.
- **AC-5** The finished bias string is truncated to at most `prompt_chars`
  (config, default 600) characters.
- **AC-6** The finished, capped bias string is exposed through an interface a
  later change can call to obtain it for a given take; this issue does not itself
  extend `Engine::transcribe` or `CommandEngine` to carry it, because doing so
  changes an interface issue #13 already shipped and is a decision this stage
  does not make (see the open question on placeholder wiring, below).
- **AC-7** The three keys `[context] conversation_turns`, `[context] file_names`
  and `[context] prompt_chars` are read from the configuration with the defaults
  6, 40 and 600; a configuration file that omits the `[context]` table entirely,
  or omits one of its keys, is valid and yields the defaults for what it omits.
- **AC-8** Context assembly does not panic on a missing transcript file, an
  unreadable pane, or a target pane outside a git repository; each of these is
  testable without a live herdr, a microphone or a real transcript, using a fake
  source for the transcript-file and pane-contents inputs.
- **AC-9** No filtering, redaction or persistence is added to the collected
  context beyond the service-turn filter in AC-2 and the caps in AC-4/AC-5: the
  bias string is not written to a log or a file beyond what the take already
  needs, and nothing here scrubs paths, names or content the prototype would have
  passed through unchanged.

## Open questions for design

The issue names these as genuinely unresolved and asks that they not be answered
here. Design must decide them; nothing above assumes an answer.

1. **How the transcript file is found reliably.** The prototype's two-step
   search — by the session id herdr reports, falling back to the newest `.jsonl`
   under the slugified working directory — was measured to have a hole: the id
   can change while the session runs and can name a file that does not exist yet.
   AC-1 requires that the transcript be found "when it can be located"; it does not
   specify the discovery algorithm.
2. **Agents other than the one proven.** Where a conversation lives on disk for
   an agent other than the one measured is unknown. AC-1 and AC-3 are written
   against "the proven agent" and "an agent has no readable transcript" without
   naming which other agents exist or how their transcripts, if any, would be
   found.
3. **What happens when no conversation can be found at all** — neither a
   transcript nor usable pane content. AC-8 requires that this not panic; it
   deliberately does not choose between failing the take, proceeding on file
   names alone, or reporting the gap once rather than every time. The issue lists
   all three as candidates without picking one.
4. Privacy is not left open — the owner's instruction (keep it as the prototype
   does, nothing clever, let the context stay small) is encoded directly in AC-9
   and is not a question for design.
5. **How the bias string reaches the engine.** `src/stt/command.rs` already
   substitutes named placeholders — `{audio}`, `{model}`, `{language}` — into a
   user-configured argument list at `render()` (`src/stt/command.rs:15-34`), so a
   `{prompt}` placeholder carrying the bias string is a plausible, visible next
   step. It is not decided here: taking it means widening `Engine::transcribe`'s
   signature (or finding another way to carry a per-take value that
   `CommandEngine` cannot bake in at construction the way it does the model and
   the language), and the not-yet-built `candle` and `http` engines would need
   the same treatment. This AC set neither assumes a `{prompt}` placeholder nor
   rules one out.

## Out of scope / noticed

- Wiring the bias string into `Engine::transcribe` — a `{prompt}` placeholder in
  `CommandEngine::render`, or the equivalent for `candle` (#15) and `http` (#16),
  still open — is not an AC here; see the open question on placeholder wiring,
  above. Issue #13, which shipped the trait and the `command` engine, is closed.
- Updating `docs/design.md` section 4 to state the pane-contents source
  explicitly (it currently reads as though the transcript is the only source) is
  a design-stage document change, not something this stage edits.
- The rewrite stage's own prompt, which in the spike carries `CTX_CONV`
  separately from the whisper bias string, stays out of bounds per the issue.
