# AC_104 — One settings popup

One pull request for four issues: #104 (change the whole configuration, including both
models, from one popup), #103 (switch the microphone from a popup opened by a key), #46
(choosing a model leaves the engine untouched, so a successful download can break a
working setup) and #49 (`write_model_key` is untested). The microphone is one section of
the settings popup. The input is GitHub; none of the four issues has a comment.

References such as [E9] point to `tasks/104/AC_104_evidence.md`, where each fact is tied to
a path and line or to the command that produced it.

## As-is

**Configuration.** Every setting lives in `config.toml` and is changed by hand. It has eight
sections: `[audio]`, `[stt]`, `[rewrite]`, `[ui]`, `[delivery]`, `[context]`, `[ptt]`,
`[record]` [E1]. Values are strings, booleans, integers, one float, and two arrays of
strings (`[stt] command`, `[rewrite] command`); `[stt] token` and `[rewrite] token` are
secrets [E2]. `config::load` returns every default, without an error, for a file that cannot
be read or does not parse, and it raises two values to a floor [E3]. Only `Deserialize` is
derived on the configuration types [E1].

**What the tree already holds.** A writer edits one or more keys of the file in place,
refuses an edit whose result does not load as the configuration, refuses a file it cannot
read instead of replacing it, and has tests [E5]. A `reload` request makes the running
daemon re-read the file, apply `[audio]` between takes and name every other changed section
as needing a restart [E6]. The recorder takes new `[audio]` values through its own order
queue, and a list of the machine's inputs by name exists [E6, E7]. A separate microphone
popup is built on those: the command `mic`, an action `mic` and a pane `mic` in the
manifest, a fourth binding in `setup` on `prefix+shift+i`, and a line in the usage text
[E7].

**The speech-model chooser.** The pane `model` lists six catalogue models and, for the one
chosen, downloads it and writes `[stt] model` [E8]. It never writes `[stt] engine`, and `run`
has no test [E8]. With the default `engine = "command"`, the configured model name is used
only when the command contains `{model}`, and then as a whisper.cpp file name, so a
catalogue download leaves a setup that does not use it (#46) [E9].

**The rewrite model.** `[rewrite] model` can be changed only by editing the file. `[rewrite]
url` is the complete address the engine posts to, ending in `/v1/chat/completions`, not a
base address [E10]. The configured server answers `GET /v1/models` with entries that carry
`id`, `object` and `owned_by` only; nothing in an entry separates a chat model from an
embedding model [E11]. Calls to other servers carry a time bound, and the engine's is thirty
seconds [E10, E12].

**Keys, actions and panes.** herdr has no binding type that opens a plugin's declared pane;
an installed plugin opens one with a manifest action whose command runs `herdr plugin pane
open` [E13, E14]. `setup` writes `plugin_action` bindings [E16]. Three points about opening
a pane were not established [E15].

**Input in a popup.** Every interactive read in the binary is a line read that needs Enter
[E17].

## To-be

- One action, `settings`, titled "herdr-voice: settings", opens one popup on a key,
  `prefix+shift+s`, which `setup` offers as its fourth binding.
- The popup lists the sections, then the keys of the one chosen, each with its current value,
  marks the values that are defaults, and lets a key be changed in place.
- The microphone is chosen in that popup by name, and the next take records from it without
  a restart. The speech model is chosen there from the catalogue, and the rewrite model from
  the list the configured server serves.
- Every change says whether it applies to the next take or needs a restart, and which.
- No separate microphone command, action, pane or binding remains.

## Readings chosen where the text allows two

- **C1. Arrow keys and Esc.** #103 says the popup is driven by arrows or a number, Enter and
  Esc. The binary reads whole lines, and a terminal delivers Esc and arrows to a line read only
  after Enter [E17]. The popup is driven by a number and Enter, with Esc before Enter leaving;
  an arrow key followed by Enter is read as Esc. Arrow keys without Enter are out of scope.
- **C2. Array-valued keys.** #104 says "a key can be changed in place". The two keys that hold
  arrays are shown and are changed in the file (AC-43).
- **C3. "Set" and "default".** A key is "set" when it appears in the file, whatever its value,
  and a "default" when it does not; comparing the value with the default would call a key
  written on purpose a default.
- **C4. `[rewrite] url` is the whole endpoint.** The list is at the models path of the same
  server, so its address is derived from `[rewrite] url` by replacing the trailing
  `/chat/completions` with `/models` [E10]. An address that does not end that way has no list
  address, and AC-35 applies.
- **C5. #46.** #46 allows writing `[stt] engine` alongside the model, or refusing and saying
  which engine serves it and what else must change. The popup does the second for every engine
  but `candle`: it does not switch the engine on its own.
- **C7. Keys that have a chooser.** `[audio] input`, `[stt] model` and `[rewrite] model` open
  their own chooser (AC-15 to AC-20, AC-28 to AC-30, AC-33 to AC-35) and are not changed by
  typing a value, so a model name cannot be written for an engine that will not use it (#46).
  Every other scalar key is changed by typing (AC-25).
- **C6. "Next take" for a speech or rewrite model.** The speech engine and the rewrite engine
  are built once and kept [E6]. #104 Done 1 says the next take uses the models; To-be 6 lets a
  change be reported as needing a restart and asks that the restart be named. After the step
  the popup names, the next take uses the model; the restart is herdr's, because the daemon is
  started by herdr; the daemon does not replace a running engine.

## Decisions the run needs

Each is given as context, problem, decision, reason.

**D1. The shape of the run.**
Context: #103 and #104 share a writer, a reload mechanism and a way to open a popup from a
key; #49 tests the writer and #46 changes the speech-model choice.
Problem: two popups and two pull requests would split what one popup does.
Decision: one popup and one pull request, from this branch with `feat/103-mic-popup` merged
in, closing all four issues.
Reason: the writer, the reload request and the recorder's reconfigure are what the popup is
built on, and the owner wants one entry point.

**D2. How the daemon learns of a change.**
Context: the configuration is read once at start and held by several threads [E6].
Problem: re-reading the file before every take puts file access on the path of the keypress
and cannot apply a speech-model change without replacing the resident engine.
Decision: the popup sends a `reload` request after a successful write; the daemon re-reads,
applies `[audio]` between takes, and names the other changed sections as needing a restart.
Reason: one mechanism for every key, and its reply is what lets the popup say truthfully
whether a change applies. A file edited by hand is not picked up until a restart.

**D3. How a key opens the popup.**
Context: herdr has no binding type that opens a plugin's declared pane [E13]; an installed
plugin does it with an action whose command runs `herdr plugin pane open` [E14].
Problem: without an action a key has nothing to bind.
Decision: one manifest action, `settings`, whose command opens the pane, bound as a
`plugin_action` the way `setup` binds the others.
Reason: it is the mechanism herdr offers. Whether `pane open` honours the pane's popup
placement without `--placement` is not established [E15].

## Out of scope / noticed

- `status` is also declared in the manifest and answers `not implemented yet`. The issues do
  not mention it; it is left alone.
- Arrow keys without Enter are issue #115.
- The rewrite server's list can include models that cannot rewrite text, such as an embedding
  model, and the response does not mark them [E11]. The popup lists what is served.
- `config::load` raises two values to a floor [E3]. The popup shows the value in the file; the
  daemon may use a larger one.
- The pane `model` ("Choose a speech model") is not asked to be removed and keeps working,
  through the same chooser the popup uses.
- Windows behaviour of the popup is not part of the manual verification, which the issues
  limit to macOS.
