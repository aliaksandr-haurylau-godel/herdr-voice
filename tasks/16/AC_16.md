# AC_16

## as-is

`stt::resolve_with` (`src/stt.rs:106-132`) refuses `[stt] engine = "http"` with
`EngineError::NotBuilt { engine: "http", issue: "issue #16" }` — no request is
ever sent. `Stt` (`src/config.rs:53-63`) has no key for an endpoint address, a
token, or a model name to send in a request; `[stt] model` (`src/config.rs:55`)
is a local-model identifier only, resolved to a file name
(`ggml-<model>.bin`) by `stt::model::locate` — meaningless for an endpoint,
which has no local file. `stt::locate_configured_model`
(`src/stt.rs:87-96`) already skips model-file lookup for anything other than
`engine = "command"`, so the `http` engine inherits that for free: no local
file is ever sought for it.

`Cargo.toml:21` already carries `ureq = { version = "2", features = ["json"]
}`, added by issue #36 for the rewrite stage's `http` engine
(`src/rewrite/http.rs`). No second HTTP client dependency is needed — the
issue's own text, written before #36 landed, assumed one would have to be
added; that is no longer true.

`src/rewrite/http.rs:22-45` is the nearest precedent in this codebase for an
HTTP-backed engine: a dedicated `ureq::Agent` per engine instance, pooling
disabled, a fixed timeout (`src/rewrite/http.rs:20`, 30 seconds, "a bound
turns a hang into a message rather than a leaked thread — the same reason
#28 exists"), and an error enum with a `Failed` variant (connection or status
failure) and a variant for a response that does not parse as expected.

## to-be

`[stt] engine = "http"` posts a take's 16 kHz mono WAV to a configured
address, in the OpenAI Whisper transcription API's shape, and reads the
transcript back from the JSON response. Configuration for the address, an
optional token, and the model name sent in the request are settled, not
provisional:

- `[stt] url` — the endpoint address. Empty means unconfigured.
- `[stt] token` — an optional bearer token. Empty means no `Authorization`
  header.
- `[stt] http_model` — the model name sent in the request body. Separate
  from `[stt] model`, which keeps its existing meaning (a local-model
  identifier for `engine = "command"`) and is not read by the `http` engine.

## requirements

Taken from the issue body directly:

1. "Take the configuration for an endpoint, with names the owner has
   agreed to." — settled above; not provisional.
2. "Send a 16 kHz mono WAV and read a transcript back." — the OpenAI Whisper
   transcription API contract: `POST` to `[stt] url`, `multipart/form-data`
   with a `file` field (the WAV), a `model` field (`[stt] http_model`, when
   non-empty), and a `language` field (`[stt] language`, when not `"auto"` —
   mirroring how `command::render` already treats `"auto"` as a value these
   programs take literally rather than a value to omit,
   `src/stt/command.rs`). Response: JSON, the transcript read from a `text`
   field.
3. "Tell apart, by message: an endpoint that is not configured, one that
   refuses the connection, one that answers with an error, and one that
   answers with something unreadable. Each names what to do next." — four
   distinct, named cases.
4. "Respect `[stt] model` and `[stt] language` as #13 wired them." — read
   literally against the as-is section, this cannot mean `[stt] model`
   itself, which is a local-model identifier with no meaning for an
   endpoint; it is read here as "respect the same *kind* of configuration
   #13 established" — a model identifier travels with the request
   (`[stt] http_model`, the owner's own naming decision) and `[stt]
   language` travels unchanged. Flagged as a reading, not silently chosen.
5. "Run its tests without a network, like every stage before it." — a
   scratch local listener, the same double `rewrite::http`'s own tests use
   (`src/rewrite/http.rs`, `respond_once`/`respond_once_with_status`).

## acceptance criteria

- **AC-1.** `[stt] engine = "http"` no longer returns
  `EngineError::NotBuilt`; `stt::resolve_with` builds a working engine when
  `[stt] url` is non-empty.
- **AC-2.** An empty `[stt] url` is a distinct, named case — "not
  configured" — not a connection failure.
- **AC-3.** A real 16 kHz mono WAV, POSTed as `multipart/form-data` to
  `[stt] url` with a `file` field, a `model` field carrying `[stt]
  http_model` when it is non-empty, and a `language` field carrying `[stt]
  language` when it is not `"auto"`, and a JSON response `{"text": "..."}`
  read back, yields that string as the transcript.
- **AC-4.** `[stt] token`, when non-empty, is sent as an `Authorization:
  Bearer <token>` header; when empty, no such header is sent.
- **AC-5.** A connection that refuses, times out, or is otherwise
  unreachable is a distinct, named case from a response that arrives with a
  non-2xx status, which is distinct from a 2xx response whose body does not
  parse as the expected JSON shape (missing or non-string `text`). Three
  cases, three messages, none of them naming the same thing.
- **AC-6.** Every message from AC-2 through AC-5 names what to do next
  (`CLAUDE.md`, "Rules for the code").
- **AC-7.** A bound exists on the request so an endpoint that accepts a
  connection and never answers turns into a message rather than a hang
  (`src/rewrite/http.rs:18-20`'s stated reason, applied here).
- **AC-8.** Every test in this issue's diff runs against a local scratch
  listener; none opens a real network connection or depends on a real
  Whisper-compatible server being reachable.
- **AC-9.** `doctor` no longer reports `[stt] engine = "http"` as "not built
  yet"; it reports the same class of configuration-state check `[stt]
  engine = "command"` already gets (a working configuration is `Ok`, an
  unconfigured one is `Missing` naming what to set) — mirroring the fix
  issue #36 made to `doctor::rewrite_finding`'s `"http"`/`"command"`
  branches (`src/doctor.rs`).

## Out of scope / noticed, not turned into a criterion

- The built-in `candle` engine. Issue #15, unrelated.
- A second HTTP client crate. `ureq` already exists in `Cargo.toml`; this
  issue's own text assumed one would need adding, written before issue #36.
- Anything about `[rewrite]`'s `http` engine (`src/rewrite/http.rs`). A
  different stage, already built; this issue is the recognition side.
- A live measurement against a real Whisper-compatible server, recorded in
  `docs/evidence.md` — not named by the issue's "Done when" the way #36's
  was; `docs/evidence.md` is updated only if a measurement is actually made.
