# AC_41 — `setup` prints the keybinding snippet and offers to append it

## as-is

**The action exists and does nothing.** `herdr-plugin.toml:48-53` declares the
action `setup`, title `Dictation: setup`, `contexts = ["global"]`, command
`["target/release/herdr-voice", "setup"]`. The binary parses the subcommand
(`src/main.rs:97`) and then falls into the arm that covers everything not built
yet (`src/main.rs:174`): it writes `setup: not implemented yet` to standard error
and exits `NOT_IMPLEMENTED`, which is 69 (`src/main.rs:108`). `setup` is absent
from the `IMPLEMENTED` list at `src/main.rs:118`. No snippet-printing or
configuration-writing code exists anywhere in `src/`.

**Two documents already promise the behaviour.** `docs/design.md` section 7 ends
with "Keybindings are **not** part of this file. A herdr plugin manifest cannot
declare keys, so they live in the user's herdr configuration; the `setup` action
prints the exact snippet and offers to append it." `README.md:44-45` repeats it
for the person installing the plugin.

**What herdr accepts as a binding.** Established by reading the default
configuration embedded in the herdr 0.9.0 binary and the live configuration on
the development machine. A binding is a `[[keys.command]]` table with the fields
`key`, `type`, `command`, `description`, and `width`/`height` for popups only.
`type` accepts exactly `shell`, `pane`, `popup` and `plugin_action`. A plugin
action is addressed as `<plugin id>.<action id>` — for this plugin,
`haurylau.voice.ptt` and so on. The plugin id is `herdr-plugin.toml:1`.

**Where that configuration lives.** The herdr binary states
`Env: HERDR_CONFIG_PATH overrides config file path`; without it the path is
`herdr/config.toml` under `XDG_CONFIG_HOME`, and under `~/.config` when that
variable is unset.

**What herdr does with a configuration it cannot parse.** It keeps the previous
one: the binary's diagnostic strings are `invalid; keeping current config` and
`unreadable; keeping current config`. `herdr config check` validates the file and
prints diagnostics. A changed file reaches the running server through
`herdr server reload-config`, or the `reload_config` binding, `prefix+shift+r` by
default.

**A `global` action cannot hold a conversation.** Established by running it:
`herdr plugin action invoke haurylau.voice.setup` returned a record with
`status: running` and printed nothing of the plugin's own output; the plugin's
standard output, standard error and exit code appeared afterwards only in
`herdr plugin log list --plugin haurylau.voice`, as
`"stderr":"setup: not implemented yet\n"`, `"exit_code":69`. There is no terminal
on that path, so a question asked there is asked to nobody. This matches the
decision already recorded for the Linux check in `docs/decisions.md`.

**A pane, unlike an action, has a terminal, and anything can ask herdr to open
one.** `herdr plugin pane open --plugin <id> --entrypoint <id>` opens a pane the
manifest declares; run against this plugin's declared `status` pane it answered
`{"id":"cli:plugin","result":{"type":"ok"}}`. The pane's process left no record in
`herdr plugin log list` — panes run in a terminal of their own rather than being
captured the way an action is. `docs/design.md:61-62` already lists `setup` among
the manifest panes, alongside `status` and `download`.

**How `setup` is reached on a machine where no key is bound yet.** herdr has no
menu or palette of plugin actions: `herdr plugin action list` and
`herdr plugin action invoke` are command-line commands, and nothing in the binary
offers the actions in its own interface. So the first reach for a freshly
installed plugin is `herdr plugin action invoke haurylau.voice.setup` from a
terminal — the path that has no terminal of its own — and the snippet this action
prints is what makes every later reach a keypress.

**Keys collide in practice, and the collision is invisible.** On the development
machine `prefix+g` is already bound to another plugin's action, and `prefix+g` is
also herdr's own default for `goto`. herdr's embedded default configuration warns
in prose: "Most reliable direct bindings are ctrl+letter, function keys, and
explicit modified chords. alt+..., cmd/super, and punctuation-with-modifiers may
depend on your terminal/tmux setup." Binding a key for this plugin took three
attempts on 2026-09-10: `alt+v` did nothing, `alt+g` typed `©`, `ctrl+g` worked.

**Argument parsing is first-argument only.** `parse` at `src/main.rs:89` matches
on `args.first()` and ignores everything after it; a flag is read separately from
the argument vector, as `--choose` is at `src/main.rs:171`.

## to-be

A person who has installed the plugin can reach a visible, interactive `setup`,
read the exact block their herdr configuration needs, answer one question, and
have the block appended — or be told precisely why it was not. Running it a
second time changes nothing and says so. When a key in the snippet is already
bound to something else, `setup` says which, and does not shadow it. Nothing
about the binding has to be worked out from herdr's documentation.

## requirements

**Asked by the issue.**

- Print the exact herdr keybinding snippet for this plugin's actions.
- Offer to append it to the user's herdr configuration.
- Append idempotently: never duplicate a binding that is already there.
- Name the file changed and what was added.
- When the configuration cannot be read or written, say which file and why,
  rather than failing silently.
- Tests against a temporary configuration file, covering the already-present case
  and the unwritable case.

**Implied, and included because the issue's "done when" cannot be met without it.**

- A path by which the offer reaches a person and their answer reaches the plugin.
  The action path cannot carry it and the pane path can, both established above.
- Resolution of the configuration file's path, including an override, without
  which the required tests cannot run against a temporary file.

**Decided by the owner on 2026-09-16**, because the issue places the naming of
keys outside this stage's bounds:

- The snippet names three actions: `ptt` on `ctrl+g`, `dictate` on `prefix+i`,
  `cancel` on `ctrl+shift+g`.
- The offer is made in a popup pane declared in the manifest.

`prefix+i` replaced a first choice of `prefix+g`, which is taken twice over, and a
second choice of `prefix+v`, which is herdr's default for `split_vertical`.
`ctrl+g` is the chord already proven to reach the binding on the development
machine.

## acceptance criteria

**AC-1** `setup` prints a snippet of three `[[keys.command]]` blocks: `ptt` on
`ctrl+g`, `dictate` on `prefix+i`, `cancel` on `ctrl+shift+g`, each with
`type = "plugin_action"`, a `command` of `haurylau.voice.<action id>` and a
`description`.

**AC-2** The plugin id and the three action ids in the printed snippet are the
ones `herdr-plugin.toml` declares. A test fails if the manifest and the printed
snippet disagree.

**AC-3** herdr accepts the printed snippet: appending it to a configuration file
and running `herdr config check` against that file reports no diagnostic about
the appended block.

**AC-4** The offer is made where a person can see it and answer it. Invoking
`setup` through herdr — `herdr plugin action invoke haurylau.voice.setup`, or a
key bound to that action — ends with a visible pane on the screen in which the
snippet is shown, the question is asked and the answer is taken. The manifest
declares that pane, and `herdr plugin pane open --plugin haurylau.voice
--entrypoint setup` opens it.

Which process does which half is the design's choice and not fixed here: the
action may ask herdr to open the pane and exit, or the pane may do everything.
What is fixed is that a person who invokes `setup` and never opens a terminal
gets the snippet and the question, and that no fourth keybinding is required to
get there.

**AC-5** Appending is idempotent. When a binding for one of the three actions is
already present in the configuration, `setup` does not add a second one, and says
which ones were already there.

**AC-6** After appending, `setup` names the file it wrote and the bindings it
added.

**AC-7** When a key the snippet names is already bound to a different command,
`setup` reports which key and what it is bound to, and does not append that
binding. The other bindings of the snippet are unaffected.

**AC-8** When the configuration file exists and cannot be read, or cannot be
written, `setup` names that file and the reason on the surface the person is
looking at, and exits with a code that distinguishes the failure from success.
When the failure happens before there is a pane to say it in — herdr refuses to
open the pane, or the plugin is not registered — the reason still reaches
`herdr plugin log list`, which is the only surface left.

**AC-9** When the configuration file does not exist, `setup` creates it with the
snippet and says that it created it.

**AC-10** After a successful append, `setup` says what makes the binding live —
`herdr server reload-config`, or the `reload_config` binding — because a binding
written to a file that the running server has not reread does nothing, and
nothing on the screen would say so.

**AC-11** The configuration file's path is resolved as `HERDR_CONFIG_PATH` when
set, then `herdr/config.toml` under `XDG_CONFIG_HOME`, then under `~/.config`.
The printed messages name the path that was resolved.

**AC-12** Tests cover, against a temporary configuration file: a clean append, a
second run over the result of the first, a file that is not writable, a file that
does not exist, and a key already bound to a different command.

## Out of scope / noticed

- The `mic` and `model` chooser panes, stubbed at the same line, `src/main.rs:174`.
- Registering the plugin with herdr — `herdr plugin link` or `herdr plugin install`.
- Removing a binding this action added. The issue asks only to append.
- The older shell prototype's bindings on the development machine run code outside
  this repository and are deliberately left alone; `setup` has no business with
  bindings it did not write.
- `README.md:44-45` says "two lines go into your herdr configuration", which is
  neither the count nor the shape of what is added. It becomes wrong the moment
  this lands.
