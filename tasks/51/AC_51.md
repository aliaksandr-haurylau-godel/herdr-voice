# AC 51 — corrected terms arrive without markup around them

## As-is

**Nothing touches the reply except a trim.** `src/rewrite/http.rs:209-210`
returns `text.trim().to_string()` for `choices[0].message.content`. The daemon
delivers the returned text verbatim (`src/daemon.rs:1227-1229`
takes `Ok(text)` as `Rewrite::Ran { text }`). A search of `src/` for a backtick
trim or a markup strip finds none.

**The prompt asks for no markup and says nothing against it.** The last
sentence of `PROMPT` is "Reply with the corrected transcript only, without the
delimiters, nothing else." (`src/rewrite/http.rs:39-40`).

**What the issue reports:** on 2026-09-14, `google/gemma-4-e4b`, three mangled
technical terms in one dictated sentence all came back repaired and all wrapped
in backticks, twice identically.

**What this run observed** (2026-10-21, macOS, this machine, `google/gemma-4-e2b`
because the model above is not loaded): a take with three mangled terms, with and
without a bias string, two requests each, came back with no backtick. The defect
is not reproduced on that model.

## To-be

A reply from the `http` engine that carries backticks the take did not contain is
delivered without them. A backtick the speaker dictated is delivered.

## Requirements

Asked by the issue: markup around a repaired term is not delivered; a test pins
it through a recorded call; whatever the mechanism, it does not strip characters
the speaker actually dictated.

Implied, not asked: nothing is added.

## Acceptance criteria

- **AC-1** A recorded reply whose repaired terms are wrapped in single backticks,
  for a take that contains no backtick, comes back from `HttpEngine::rewrite`
  with those backticks removed and every other character of the reply unchanged
  (AC-4 states the one exception, edge whitespace).
  The test serves the reply from a listener on a real socket, as the existing
  tests in `src/rewrite/http.rs` do.
- **AC-2** The same holds for a run of backticks around several words, and for
  triple-backtick fences, in a take that contains no backtick.
- **AC-3** When the take contains a backtick, the reply is returned exactly as the
  engine returns it today, trimmed and otherwise unchanged. This is the boundary:
  a character the speaker dictated cannot be removed, because with a backtick in
  the take the engine cannot tell the speaker's backticks from the model's.
- **AC-4** After the strip the reply is trimmed again, as it is trimmed today, so
  a fenced reply `"```\nfoo\n```"` is delivered as `foo`. Apart from that edge
  whitespace, no character other than a backtick is removed: double and single
  quotes, asterisks, tildes, hyphens, underscores and whitespace inside the reply
  are returned as they came.
- **AC-5** A reply in Cyrillic with backticks around a Latin term comes back whole,
  with the Cyrillic unchanged.
- **AC-6** A reply that is only backticks, or backticks and whitespace, is returned
  as the empty string, the same as an empty reply is today.
- **AC-7** The prompt text is unchanged by this run.
- **AC-8** `docs/evidence.md` records, with platform and date, the run of the
  shipped engine against a listener that answers with a backticked reply, and the
  take and reply for the case where the take contains a backtick. If the live
  series on the model the issue names has not been taken, the section says so.

## Ambiguities and the reading taken

- "Whether the fix belongs in the prompt or in a strip": a strip. The issue says a
  prompt instruction is not enforcement. Adding a line to the prompt changes what
  is sent to the owner's model by default, which this issue does not ask for.
- "Does not strip characters the speaker actually dictated": read as the rule in
  AC-3. The engine receives the transcript, so it can compare.
- Which engines: the `http` engine, which the issue names and whose prompt is the
  cause. The `command` engine runs a program the person wrote
  (`src/rewrite/command.rs`), and its output is that program's to decide.

## Out of scope / noticed

- Other markup a model could add (asterisks for emphasis, a language tag after a
  triple-backtick fence) is not stripped. A fence with a language tag leaves the
  tag in the reply once the backticks are gone.
- The shortening in the same reply is #50.
