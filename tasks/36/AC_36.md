# AC_36

## as-is

The rewrite stage does not exist in the running pipeline. `src/daemon.rs`'s
`transcribe` (`src/daemon.rs:303-338` in this checkout) reads recognition's
`text` from `engine.transcribe(&take.path)` and passes it straight to
`crate::delivery::deliver(...)` after journaling `delivering_line(&text)` —
nothing in between rewrites anything. `dictate` (`src/daemon.rs:139-166`)
calls `take_bias(...)` and then `transcribe(runtime, &take)`; neither builds
nor holds a rewrite engine.

`src/config.rs`'s `Rewrite` struct (`:67-70`) declares only two fields,
`engine: String` and `agent: String`, both defaulting to `"agent"`/`"auto"`
(`:69-74` reachable via `impl Default for Rewrite`). `docs/design.md`'s §7
configuration table additionally shows `model`, `args`, `skip_if_plain` and
`prompt_file` under `[rewrite]` — none of these four exist in the config
reader today; the table is aspirational.

`src/doctor.rs`'s `rewrite_finding` (`:259-296`) diagnoses configuration only:
`"off"` reports `Ok`; `"agent"` searches `PATH` for a candidate agent binary;
`"http" | "command"` reports `Missing`, `"the {engine:?} engine is not built
yet; use \"agent\" or \"off\""`. Nothing calls a rewrite engine anywhere in
the binary.

`docs/design.md`'s "Rewrite" section (§4) states the rule the stage follows:
fix form only — file and directory names, flags, commands, foreign technical
terms, punctuation and capitalization — never meaning, length or intent;
three engines, `agent` (a coding-agent CLI tool, one-shot), `http` (an
OpenAI-compatible endpoint, cloud or local server) and `command` (an arbitrary
external program); "a short phrase containing neither foreign terms nor names
from the context skips this stage"; "if no engine is available, the
transcript is inserted unchanged and the user is told once, not on every
take."

`spike/spike.sh`'s `rewrite()` function (`:298-332`) is the one measurement
this design rests on. It always calls `claude -p` — there is no skip
condition of any kind in the prototype, and no precedent for what "a short
phrase" or "a foreign term" means operationally. The skip rule in
`docs/design.md` was written without a prototype measurement behind it.

`bias::collect` (issue #21, merged) already assembles file names and a
conversation excerpt per take, capped at `[context] prompt_chars`; nothing
collects the git branch, the pane title or the agent kind (`docs/design.md`
states this explicitly, and the prototype's own `CTX_BRANCH`/`CTX_TITLE`/
`CTX_AGENT` fields have no equivalent in the plugin). `Cargo.toml`'s
`[dependencies]` has no HTTP client crate.

## to-be

A finished take's transcript passes through a configured rewrite engine —
`http`, pointed at an OpenAI-compatible address, or `command`, an arbitrary
external program substituting the transcript into a configured argument list
— before the text reaches `delivery::deliver`. `off` (already diagnosed as
`Ok` by `doctor`) continues to insert the transcript unchanged. A configured
engine that cannot run does not fail the take: the transcript is delivered
unrewritten, and the person is told about it once per daemon lifetime, not on
every take after the first.

## requirements

Taken from the issue body directly:

1. "Wire the rewrite step into the take path in `src/daemon.rs`, between a
   finished transcript and delivery, so it actually runs — today nothing
   calls it."
2. "`[rewrite] engine = \"http\"`: post the transcript ... to a configured
   address, in an OpenAI-compatible chat or completion shape, and read the
   rewritten text back." Configuration for the address, an optional token,
   and the model name are new keys, provisional and renameable on the owner's
   word.
3. "`[rewrite] engine = \"command\"`: run an arbitrary external program the
   way `[stt] command` already does for transcription, substituting the
   transcript in by a placeholder in a configured argument list."
4. "`[rewrite] engine = \"off\"`: the transcript is inserted unchanged;
   `doctor` already reports this as `Ok`" — unaffected by this issue.
5. "The short-phrase skip design.md already describes: a transcript with no
   foreign term and no name from the collected bias string skips the round
   trip." — Read against the as-is section above, this is not a settled
   requirement with an operational definition; it is a design-stage decision
   this issue must still make (see "What this stage has to settle," below).
6. "If the configured engine cannot run ... the transcript is delivered
   unchanged and the person is told once, not on every take. Each failure
   names what to do next."
7. "Run its tests without a network, the same rule #16 will follow."
8. Whether and how the collected bias string (`bias::collect`'s existing
   `Collected`) reaches the rewrite engine's prompt at all is explicitly
   marked undecided in the issue body ("and whatever `[context]` passes it,
   if anything does — decide against `bias::collect`'s existing shape, not a
   new one"). Not turned into a requirement here; carried to design as an
   open question.

## What this stage has to settle, not decided by the ticket or the prototype

Five items, each because the prototype has no measurement behind it or the
ticket left it open on purpose:

- **What "a short phrase" and "a foreign term" mean, operationally**, so the
  skip rule (requirement 5) is checkable at all. The prototype never skips;
  there is no reference behavior to port.
- **Whether the rewrite engine receives any collected context**, and if so,
  through what shape — `bias::Collected` as `bias::collect` already produces
  it, or a subset. Left open by the ticket itself (requirement 8).
- **What "told once, not on every take" means as a mechanism** — an
  in-memory flag for the daemon's lifetime is the minimum the wording
  supports; nothing in the ticket asks for persistence across a restart, and
  this AC does not add that requirement.
- **The exact `[rewrite]` configuration keys** for the `http` address, an
  optional token, and the model name, and for `command`'s argument list and
  its placeholder syntax. `docs/design.md`'s `model`/`args`/`prompt_file`
  names are a starting point, not a settled contract — provisional, the same
  footing `[stt] command` was introduced on (`docs/decisions.md`,
  2026-08-25, #13).
- **Which HTTP client crate**, blocking rather than async
  (`docs/decisions.md`, 2026-08-24, #3, "asynchronous runtimes are not
  [allowed], until a task appears that cannot be done without one" — this may
  be that task, but the crate itself is a design pick, not an AC).

## acceptance criteria

- **AC-1.** `daemon::transcribe` (or its replacement) calls a rewrite step
  between recognition producing `text` and `delivery::deliver` being called,
  for every take where `[rewrite] engine` is not `"off"`.
- **AC-2.** `[rewrite] engine = "http"` posts the transcript to a configured
  address in an OpenAI-compatible shape and the rewritten text, not the
  original, reaches delivery on a successful response.
- **AC-3.** `[rewrite] engine = "command"` runs a configured external program
  with the transcript substituted into its argument list by a placeholder,
  and the program's output, not the original transcript, reaches delivery on
  success.
- **AC-4.** `[rewrite] engine = "off"` continues to insert the transcript
  unchanged; no test or behavior here regresses `doctor`'s existing `Ok`
  report for it.
- **AC-5.** A transcript that the (to-be-designed) skip heuristic judges as
  needing no rewrite is delivered unchanged without the configured engine
  being invoked at all — observable as: the engine is not called.
- **AC-6.** When a configured `http` or `command` engine cannot run — refuses
  the connection, times out, answers with an error, or answers with something
  unreadable — the take still completes: the unrewritten transcript is
  delivered, and the reply is not `Reply::Error` for this reason alone.
- **AC-7.** The first such failure in a daemon's lifetime produces one
  user-visible notification (journal line, toast, or both, matching how
  other stages report); a second, later failure of the same kind in the same
  daemon lifetime does not repeat it.
- **AC-8.** Every failure message names what to do next, the same standard
  `CLAUDE.md` and every other stage's errors already meet.
- **AC-9.** Both the `http` engine's client and the `command` engine's
  process invocation are tested without a live network call or a live
  external program — a fake HTTP server or a scratch script stands in, the
  same way `bias::pane`'s and `stt::command`'s own tests do.
- **AC-10.** A real, running local OpenAI-compatible server (LM Studio or
  Ollama) rewrites a real transcript through the `http` engine, and a real
  arbitrary program rewrites one through the `command` engine — each
  verified by running it, not only by a test — recorded in `docs/evidence.md`
  with the platform, the same way every other stage's first live measurement
  was recorded.

## Out of scope / noticed, not turned into a criterion

- The `agent` engine (a coding-agent CLI tool run in one-shot mode). The issue
  says so explicitly — separate issue.
- Collecting anything beyond what `bias::collect` (#21) already collects —
  no branch, pane title or agent kind joins the rewrite prompt by way of this
  issue.
- Issue #16's STT endpoint engine, even though it and this issue's `http`
  engine will likely share an HTTP client crate — the issue says so
  explicitly, and this AC does not require coordinating the two beyond noting
  it.
- Persisting the "told once" flag across a daemon restart. Nothing in the
  ticket asks for it.
- A release tag, distribution, or anything about `README.md`'s claims about
  what the plugin needs installed — unaffected by this issue.
