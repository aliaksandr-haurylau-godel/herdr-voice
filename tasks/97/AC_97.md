# AC_97

Acceptance criteria for issue #97, read from GitHub and checked against `main` at
`3dd45b8`.

## As is

`.githooks/pre-commit` reads the private word list with

```sh
while IFS= read -r pattern; do
  case "$pattern" in ''|'#'*) continue ;; esac
  ...
done < "$root/.leakwords"
```

`read` returns non-zero when it reaches end of file on a line with no newline, so the
loop ends before the body runs for that line. If the last line of `.leakwords` has no
trailing newline, that entry is never matched against the staged diff: a commit
containing the word passes, and nothing is printed. `.leakwords` is the only file the
hook reads this way; `.github/workflows/leak-gate.yml` runs gitleaks and does not read
it.

`scripts/test-pre-commit.sh` writes every list with a trailing newline (`printf '...\n'`),
so no case reaches this line.

## To be

1. The last entry of `.leakwords` is checked whether or not the file ends in a newline.
2. A last line that is blank or a comment is still skipped, with or without a newline.
3. Every other behaviour of the hook is unchanged: the missing-file refusal, the
   messages, the exit codes, case-insensitive extended regular expressions.

## Requirements

- R1. `scripts/test-pre-commit.sh` gains a case where the matching entry is the
  unterminated last line of a file with an earlier entry, and one where it is the only,
  unterminated line; both must exit 1 with the match message.
- R2. A case with an unterminated last line that does not match exits 0 and prints
  nothing.
- R3. A case with an unterminated comment line (`#ordinary`, which would match the staged
  line if it were read as an entry) exits 0 and prints nothing.
- R4. The new cases fail against the unchanged hook (R1 only) and pass with the change.
- R5. S5: a real `git commit` in a scratch repository with `core.hooksPath` pointing at
  this checkout's hook, with a `.leakwords` whose last line is unterminated, before and
  after; recorded in `docs/evidence.md` with the platform.

## Out of bounds

- Files with CRLF line endings, a list that is a symbolic link, and patterns that are not
  valid regular expressions: none is what the issue describes.
- Rewriting the hook, and the other two checks in it (secrets, editing debris).
- Anything outside `.githooks/pre-commit`, `scripts/test-pre-commit.sh`, the run
  artifacts and `docs/evidence.md`. The note in the section for issue #64 that lists this
  as not covered is a record of that run and stays.
