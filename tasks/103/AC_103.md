# AC_103 — The microphone popup, with the configuration writer and the reload request

This is the first of two pull requests of one run. It closes #103 and #49. The second
pull request (#104 and #46) is built on it and has its own criteria. The assessment of
the whole run, with the requirements of all four issues and the readings behind them,
is `tasks/104/AC_104.md` in that second pull request; the criteria below keep the
numbers they have there, and the criteria that belong to the second pull request are
left out. The S1 gate verdicts for the whole run are recorded in `RUN_103.md`.

References such as [E9] point to `tasks/103/AC_103_evidence.md`.

## As-is

- The manifest declares the `mic` popup and the binary answers `not implemented yet`
  [E12]. The input is selected by name from `[audio] input`, per take, from the value
  the recorder was started with [E4]. Devices are listed only inside the code that
  opens one [E13].
- The daemon reads the configuration once at start and the recorder keeps its `[audio]`
  values for the life of its thread [E2, E3]. It answers requests such as `ping` [E5].
- `write_model_key` edits `[stt] model` and nothing else, has no test, reads an
  existing file that cannot be read as an empty one and then replaces it, and checks
  its result by parsing it as generic TOML, which accepts a value of the wrong type
  that `config::load` then rejects by discarding the whole file [E9, E8, E8a, E6].
- herdr has no binding type that opens a plugin's declared pane; an installed plugin
  does it with a manifest action whose command runs `herdr plugin pane open` [E15,
  E17]. `setup` offers three bindings, all `plugin_action` [E16].
- Every interactive read in the binary is a line read that needs Enter [E14].

## To-be

- One writer edits one or more keys of the configuration file in place, refuses a result
  that would not load, and is tested.
- A key opens the `mic` popup. The popup lists inputs by name, writes the choice to
  `[audio] input`, and tells the running daemon, which uses the new input from the next
  take.
- The mechanism by which a popup reaches the daemon without a restart is recorded once
  in `docs/decisions.md`.

## Requirements

What #103 and #49 ask for, and what the run needs of them: #49's tests of the writer;
#103's popup, its three stated messages, the unimplemented-command test and usage text;
#103's "next take without a restart" and "a take in progress is not cut off"; the
shared "re-read without a restart" answer in `docs/decisions.md`; how a key opens a
plugin pane, established by running herdr; the manifest check. The writer's ability to
set several keys in one edit is required here so that the second pull request (#46)
does not have to change it.

## Acceptance criteria

"Test" means a unit test in the repository that runs without a microphone, a model, a
download or a live herdr.

### The configuration writer

- **AC-1** A test writes a good edit to a temporary configuration file and finds the
  asked key changed and every other line of the original byte-identical, including
  comments and other tables. [#103 To-be 3; #49]
- **AC-2** A test whose edit would produce a file that does not load as the
  configuration finds the file on disk byte-identical to before and an error that names
  the file and the key and value refused. [#103 To-be 3; #49]
- **AC-3** The check in AC-2 is the one `config::load` applies: a TOML-valid value of
  the wrong type for its key (for example a string for `[ui] blink_ms`) is refused by a
  test. [#103 To-be 3: "re-parsed before it is written"; E8a]
- **AC-4** Replacing the guard's condition with `false` makes at least one test fail.
  [#49 Done]
- **AC-5** A test with an unwritable location (directory that cannot be created, file
  that cannot be written) finds an error that names the file and the line to add by
  hand, a non-zero outcome, and no partial file. [#49]
- **AC-6** A test with no file and no directory finds both created, holding only the
  edited key. [#49; CLAUDE.md "an absent configuration file is a valid state"]
- **AC-7** A test with an existing file that cannot be read finds the edit refused with
  the reason and the file untouched, not replaced by a file holding the one key.
  [#103 To-be 3: "without disturbing anything else"]
- **AC-8** A test that sets two keys in one edit finds either both changed or neither,
  and the parse check run once over the result. [run requirement, see above]
- **AC-9** A test finds that setting a key under `[audio]` leaves a same-named key under
  another table unchanged, and the reverse. [#103 To-be 3]

### Reaching the daemon without a restart

- **AC-10** After `[audio] input` is changed through the popup, a take started
  afterwards records from the new input with no restart of herdr or of the daemon. Test
  with a fake input source, and by hand on macOS. [#103 To-be 4, Done 1]
- **AC-11** A test in which the choice is made while a take is recording finds that take
  finishing on the input it started on, not cut off. [#103 To-be 5]
- **AC-12** `docs/decisions.md` has one entry for how the daemon learns of a changed
  configuration. [#103 Questions 1]
- **AC-13** After a change the popup says whether it applies to the next take or needs a
  restart, and what restart; a test shows that when `[audio]` changed the daemon's reply
  says it took effect, and that when another section of the file differs from what the
  daemon started with, the reply says that section needs a restart. [#103 To-be 4; the
  run's shared reload answer]
- **AC-14** When no daemon is running, a change is still written, and the popup says the
  daemon is not running and the change applies when it starts. [#103 To-be 4]

- **AC-21** The `main.rs` test no longer lists `mic` as unimplemented, `mic` is in

## Readings chosen where the text allows two

- **C1. Arrow keys and Esc.** The owner's default is a number and Enter, with Esc
  recognised before Enter. A terminal delivers an arrow key as an Esc-led sequence, so
  an arrow typed and followed by Enter is read as Esc and leaves without a change; the
  popup's prompt says to type a number. Raw terminal input is not built.
- **C3. "Set" and "default"** and the other readings of the second pull request do not
  apply here.

## Out of scope / noticed

- Choosing "the system default input" again after a name was set is not asked for in
  #103 and is not built; the person can delete the key.
- `status` is also declared and answers `not implemented yet` [E12]; it is left alone.
- A configuration edited by hand while the daemon runs stays unread until a restart.
