# AC_23

## as-is

`scripts/linux-check.sh` verifies the plugin inside a Linux container. Every
step records a row in `report.tsv`; the run prints the rows as a table and the
table is copied into `docs/evidence.md`. The issue (#23, no comments) lists six
defects. Each was read against the current script:

1. **A step can be satisfied by a record from an earlier run.**
   `await_new_log` ignores one log id (`scripts/linux-check.sh:120-141`), taken
   by `newest_log_id`, which returns the newest `dictate` record
   (`:112-116`, used at `:641` and `:716`). A run leaves two finished `dictate`
   records, one from `no-device` and one from `named-device`, so the older one
   of a previous run passes the filter and satisfies the wait before this run's
   take has finished. The `cancel` wait at `:535` passes an empty id, so any
   finished `cancel` record, this run's or an earlier run's, satisfies it
   (`last` picks the newest finished one, and an earlier run's is the newest
   until this run's has finished).
2. **The borrowed configuration is lost on failure.** The `named-device` step
   copies `config.toml` to `<plugin>-config-backup` without checking whether a
   backup is already there (`:684-687`), writes a configuration naming a device
   that does not exist, and restores the original only after the step has
   passed (`:750-754`). `fail` and `skip_as_failure` exit; `cleanup`
   (`:81-100`) does not touch the configuration. After a failure or an
   interrupt, `config.toml` names the wrong device and the backup sits beside
   it; the next run copies the wrong file over the backup, and a later
   successful run restores the wrong file as if it were the original. With that
   file in place the `no-device` step also stops exercising the branch it
   exists for.
3. **A daemon that will not stop is worked around.** After `pkill`, the wait of
   up to ten seconds for the old daemon to go (`:691-698`) does nothing when the
   time runs out, and a new daemon is started unconditionally (`:699`). The
   `no-daemon` step waits the same way (`:773-780`) and, when the daemon is
   still up, records "skipped" and carries on (`:781-782`).
4. **A hanging `herdr plugin action invoke dictate` is blamed on the plugin.**
   `INVOKE_CODE` is assigned in `named-device` (`:720`) and never read; the
   `no-device` step checks it for 124 (`:648-651`). A hang there is reported as
   "the dictate take never finished".
5. **A tab in the report breaks its columns.** `record` writes tab-separated
   fields and `print_report` reads them back with a tab as the separator
   (`:50-61`). `TAKE_SAID` is the first line of the plugin's standard error
   (`:638`), which can hold a tab.
6. **The evidence contradicts itself.** `docs/evidence.md`, section "Linux, in
   a container", opens with "Run twice on 2026-08-25 ... The plugin was built
   from revision `68fbe89`" and a few lines later says "This is the second run
   of this check. The first, on revision `e32a9b7`". "Twice" and "second" count
   different things.

No container runtime is available on the machine this runs on, and the herdr
the script drives is not installed here either.

## to-be

Each defect is gone, and the script's decisions are pinned by a test that runs
without a container.

## requirements

1. **Records.** Before an action is invoked, the script takes the set of log ids
   herdr holds for the plugin. A wait for the action's record accepts only a
   finished record whose id is not in that set. This applies to the `cancel`
   invocation, to the `no-device` `dictate` and to the `named-device` `dictate`.
   If the set cannot be read (herdr fails or answers something that is not the
   expected JSON), the run fails at that step and says so; it does not proceed
   with an empty set.
2. **Configuration.**
   - An existing backup is never overwritten.
   - The original is restored on every way the script ends: success, `fail`,
     `skip_as_failure`, an error under `set -e`, and an interrupt or terminate
     signal. It is restored by `cleanup`.
   - A configuration that was absent when the script began is absent when it
     ends.
   - A backup left by an earlier run that could not clean up (killed without a
     chance to run `cleanup`) is restored before anything else uses the
     configuration, and the script says it did.
3. **A daemon that will not stop fails the run.** In `named-device`, when the old
   daemon is still answering after the wait, the step fails, names the daemon,
   and says what to do; no new daemon is started. In `no-daemon`, a daemon still
   answering fails the step instead of recording "skipped". The wait is ten
   seconds by default and can be shortened with an environment variable named in
   the script's header, so a test need not wait ten seconds.
4. **A hanging invoke.** In `named-device`, an `invoke` that returns 124 fails the
   step with the same kind of message `no-device` gives (herdr did not return
   from invoking `dictate` within the limit), not "the take never finished".
5. **Tabs.** No field written to the report can contain a tab: `record` replaces
   each tab in its arguments with a space. A stderr line with a tab leaves the
   printed report with the same columns as any other.
6. **The evidence.** The section states, once and without contradiction, which
   runs it covers and on which revisions, using only what the section and the
   commit that wrote it already state. It says plainly which claim ("the two
   runs agreed") the grading defect weakens, and why.
7. **Tests, with stubs.** A script `scripts/test-linux-check.sh` runs the whole of
   `scripts/linux-check.sh` against stub commands (a `herdr` that keeps a log it
   can be asked about, a plugin binary, `pkill` and the package and toolchain
   commands), never against a real herdr, a real daemon or a real package
   manager, and never touching a process that is not its own. It covers each of
   requirements 1 to 5, and each case fails on the script as it is today. CI runs
   it on Linux and macOS beside the other script tests.
8. **No claim of a Linux run.** `docs/evidence.md` says in plain words that this
   change was verified with stubs on macOS and that no Linux run, container or
   real herdr was involved, and what that leaves unproven.

## out of scope

- Running the check in a container, or any change to what the steps verify.
- The `herdr` facts the script relies on (`--plugin`, `--limit`, the record's
  fields): they are taken as the issue states them.
- Other defects in the script that the issue does not list.
- Changing `docs/evidence.md` beyond the one section.

## by hand (S5)

The test script run on this machine under both the `bash` on `PATH` and
`/bin/bash`, the result read in full, and each case shown to fail on the
unmodified script. No Linux run.
