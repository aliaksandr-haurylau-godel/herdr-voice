# AC_15

## as-is

**The engine does not exist and says so.** `stt::resolve_with`'s `"candle"` arm
returns `EngineError::NotBuilt { engine: "candle", issue: "issue #15" }`
(`src/stt.rs:111-114`), whose message is "the \"candle\" engine is not built in
this version (issue #15); set [stt] engine = \"command\" and give [stt] command a
transcriber, for example: …" (`src/stt.rs:48-54`). `"candle"` is the shipped
default of `[stt] engine` (`src/config.rs:88-97`, `impl Default for Stt`), so a
fresh install refuses every take until this issue lands. `docs/decisions.md`
records the cut and the reason it must not fall back silently: "The default
engine stays `candle`, and an unbuilt engine says so rather than falling back to
a working one" (2026-08-25, #13).

> **Superseded, 2026-09-10.** The owner chose `command` as the shipped default
> once the built-in engine had been measured against `whisper-cli`
> (`docs/evidence.md`). Everything in this document about the `candle` engine
> still holds; what no longer holds is that it is what a fresh install uses. A
> fresh install now refuses every take because `[stt] command` is empty, and
> says so with a working example. AC-11 carries the second consequence.

**Nothing in the crate can run a neural network.** `Cargo.toml`'s
`[dependencies]` is `cpal`, `interprocess`, `serde`, `serde_json`, `toml`,
`ureq`. There is no tensor library, no tokenizer, no model downloader.

**The engine interface is fixed and already carries what this engine needs.**
`stt::Engine` is one method — `fn transcribe(&self, audio: &Path, bias: &str) ->
Result<String, EngineError>` (`src/stt.rs:17-19`). Everything else an engine
needs — the model, the language — is given at construction, because the path and
the bias string are the only per-take values (`src/stt.rs:3-7`). The engine is
built once, at daemon start: `stt::resolve(&loaded.config.stt, &models)` at
`src/daemon.rs:517`, its `Result` kept in `Runtime::recognition` and consulted
when a take finishes (`src/daemon.rs:44-47`, `src/daemon.rs:315-333`). A failure
there is not fatal — the daemon still answers `cancel` and `doctor`.

**The take is a 16 kHz mono WAV on disk, and nothing in this crate reads one
back.** `src/audio/wav.rs` has `encode` and `write` (`src/audio/wav.rs:14` and `src/audio/wav.rs:45`) and no
decoder: "16-bit PCM in a WAV container: what the prototype handed to a Whisper
command-line tool" (`src/audio/wav.rs:1-4`). Every engine so far handed the path
to another program, which did its own decoding.

**The model contract is whisper.cpp's `ggml`, in one file, and it is exact on
purpose.** `stt::model::file_name` is `format!("ggml-{model}.bin")`
(`src/stt/model.rs:18-20`) and `stt::model::locate` runs four checks in order
(`src/stt/model.rs:97-154`): the exact file name (a name that merely contains the
identifier is refused — `a_name_that_merely_contains_the_model_does_not_count`),
at least 1 MiB (`SMALLEST_PLAUSIBLE_BYTES`, `src/stt/model.rs:12`), the four leading bytes
`6C 6D 67 67` (`GGML_MAGIC`, `src/stt/model.rs:15`), and a `<name>.bin.sha256` sidecar when one
exists. The sidecar branch carries a comment aimed straight at this issue:
"Nothing downloads models yet, so its absence is the ordinary case rather than a
fault" (`src/stt/model.rs:136-137`), and `docs/decisions.md` says "A `.sha256`
sidecar is checked when present, and #15, which downloads, writes it"
(2026-08-25, #13). The identifier-versus-file-name split is also recorded there:
"`[stt] model` is an identifier; the file is `ggml-<model>.bin` in the models
directory".

**That contract describes a file format `candle` does not read.**
`candle-transformers` 0.11.0 carries a Whisper implementation that loads
`safetensors` (or GGUF for its quantized variant); the `ggml-*.bin` files
`whisper-cli` uses are neither. Checked against the Hugging Face API on
2026-09-09: `openai/whisper-large-v3-turbo` and the other `openai/whisper-*`
repositories ship `model.safetensors`, `config.json` and `tokenizer.json` — three
files, not one, and none of them begins with the `ggml` magic. `lmz/candle-whisper`,
the repository candle's own Whisper example points at for quantized weights,
holds `tiny` only. So the existing contract's *checks* (exact name, plausible
size, a format check that catches a truncated download, a digest when one is
known) are all directly applicable, but its *constants* — one file, that name
template, that magic — are not. Reconciling the two without loosening the
contract is this issue's first design problem, not an implementation detail.

**Nothing locates a model for the built-in engine.**
`stt::locate_configured_model` returns `Some(..)` only when `stt.engine ==
"command"` **and** the argument list contains `{model}` (`src/stt.rs:87-96`).
For `engine = "candle"` it returns `None`, and `doctor::model_finding_from`
prints `State::NotUsed`: "[stt] model (…) is not used by this configuration;
nothing in it asks for one" (`src/doctor.rs:220-242`). A test pins that
behaviour for `candle` explicitly —
`the_model_line_is_not_used_when_the_engine_is_not_built`
(`src/doctor.rs:509-522`) asserts `State::NotUsed` for both `candle` and `http`.
It is true today and false the moment this issue lands.

**The model chooser is declared and unbuilt.** `herdr-plugin.toml` declares a
pane `model`, title "Choose a speech model", `command = ["target/release/herdr-voice",
"model", "--choose"]`, placement `popup`, 70% × 16. `src/main.rs` parses `model`
into `Command::Model` (`src/main.rs:92`) and routes it to the arm that prints
"model: not implemented yet" and exits `NOT_IMPLEMENTED` (69) (`src/main.rs:161-168`, and `NOT_IMPLEMENTED` at `src/main.rs:101`). `parse` looks only at the first argument, so `--choose` is read by
nothing. Two tests pin the unbuilt state:
`the_commands_this_issue_implements_are_not_in_the_unimplemented_arm` asserts
`model` is absent from `IMPLEMENTED` (`src/main.rs:211-215`), and
`the_usage_text_names_every_implemented_command` (`src/main.rs:228-233`) walks `USAGE`,
which does not mention it. `scripts/check_manifest.py` checks that the binary
accepts every command the manifest names; it does not check that a command does
anything.

**No download machinery of any kind exists.** Nothing in the crate fetches a
file. `ureq` 2 with the `json` feature is already a dependency, added for
`[rewrite] engine = "http"` (`docs/decisions.md`, 2026-09-04, #36: "blocking,
default TLS backend (`rustls`) … `ureq` needs no executor and no native TLS
dependency").

**The measurement this engine will be compared against already exists.**
`docs/evidence.md`, "Recognition, by hand on macOS": `whisper-cli` from Homebrew
against `ggml` 0.20.2 on Metal, `ggml-large-v3-turbo.bin`, transcribed a
70-second Russian take in 1.65 s with a bias prompt and 1.53 s without; and
"Recognition is not the slow stage. 1.5 to 1.8 seconds for 70 seconds of speech,
on Metal." The same section records that a bias prompt is what restores English
technical terms, and that a minute of room tone produced confident hallucinated
text.

**The repository states the gap publicly.** `README.md:47-49`: "Speech
recognition needs an external engine until the built-in one is built, which is
tracked as issue #15." `docs/decisions.md` (2026-08-25, #13): "No release is
tagged while the built-in engine is absent."

## to-be

`[stt] engine = "candle"` — the shipped default when this was written, see the
note in the as-is above — transcribes a finished take
inside this process: the plugin reads the 16 kHz mono WAV the recorder wrote,
runs a Whisper model held in the daemon, and returns a transcript, with no
external program invoked and no network call on the take path. The model that
runs is one a person chose from a list showing each model's size, which this
plugin downloaded and verified before first use; a download that stopped early,
arrived corrupt, or is the wrong file is a named failure at verification time,
never a confusing one at load time. `[stt] model` and `[stt] language` keep the
meaning #13 gave them. Nothing about context, rewrite or delivery changes, and
the whole test suite still passes with no model file on disk, no network
reachable and no GPU.

## requirements

Taken from the issue body, separated from what it implies.

**Asked for directly:**

1. "Transcribe a 16 kHz mono WAV locally, with no external program."
2. "Offer a list of models with their sizes on first run, download the chosen
   one, and verify it: exact file name, and an integrity check that makes a
   truncated download a named failure rather than a confusing one at load time.
   The exact-name contract is already in place from #13 and must be honoured,
   not loosened."
3. "Respect `[stt] model` and `[stt] language` as #13 wired them."
4. "Be measurable against whisper.cpp, which is #2." — a property of the design,
   not work done here; #2 is a separate issue.
5. "The tests must run without a model, as every stage does." Read together with
   `CLAUDE.md` ("Anything that cannot be covered that way … is verified by hand")
   and with the run brief, this also means without a network and without
   assuming a GPU.
6. "macOS first."

**Implied by the repository's own standing rules, not by the ticket's wording:**

7. Every failure names what to do next, and none of it panics in the daemon
   (`CLAUDE.md`, "Rules for the code"). Applied here that names concrete cases:
   a missing model, an interrupted or corrupt download, an unsupported device or
   architecture, a model file that does not match the identifier.
8. `doctor` must stop reporting `model … is not used by this configuration` for
   `engine = "candle"`, because after this issue it is used. `src/doctor.rs:509-522`
   pins the opposite today. This is a direct consequence of requirement 1, not a
   new feature.
9. `README.md:47-49` and `docs/decisions.md`'s "no release is tagged while the
   built-in engine is absent" describe a state this issue ends. The README
   sentence must stop saying an external engine is needed.

**Reserved for the owner, proposed provisionally here** (the same footing
`[stt] command` was introduced on — `docs/decisions.md`, 2026-08-25, #13):

10. The exact set of model identifiers offered on first run, and the size shown
    for each.
11. Where a model is downloaded from.

Both are user-visible names and a network destination. The run brief states the
owner is not reachable from this session and instructs that concrete defaults be
proposed, marked provisional and renameable, and recorded in `docs/decisions.md`
in the four-part form — rather than the run blocking on an answer nobody can
give. The proposal carried into design, from the file listing and sizes read off
the Hugging Face API on 2026-09-09:

| identifier | `model.safetensors` | repository |
|---|---|---|
| `tiny` | 151 MB | `openai/whisper-tiny` |
| `base` | 290 MB | `openai/whisper-base` |
| `small` | 967 MB | `openai/whisper-small` |

## What this stage hands to design, undecided

Six items. None is settled by the ticket, by the prototype, or by an existing
decision, and each changes what gets built.

- **How the `ggml`-shaped model contract in `src/stt/model.rs` extends to a
  model that is several files in a different format**, without loosening any of
  the four checks it makes. The contract's checks apply; three of its constants
  do not (see as-is). Design must say what the exact name is, what the format
  check reads, and whether `locate` grows a notion of per-engine model shape or
  the candle engine gets its own locator beside it.
- **Which crates, at which versions, and what they cost.** `candle-core`,
  `candle-nn` and `candle-transformers` are all at 0.11.0 and
  `candle-transformers` already contains a Whisper implementation; `hf-hub` is at
  1.0.0 and `tokenizers` at 0.23.2. Whether all four are taken, whether the
  download uses `hf-hub` or the `ureq` already in the tree, and what this does to
  build time and binary size, are design's to decide and to state.
- **Where the log-mel spectrogram comes from.** Whisper's encoder takes a mel
  spectrogram, not samples, and candle's own Whisper example ships a
  precomputed mel filterbank as a binary blob beside the example rather than
  computing one. Nothing in this repository has such a blob, and nothing computes
  a filterbank. This is a concrete missing piece, not a detail.
- **How the model is chosen, and what "first run" means as a mechanism.** The
  manifest already declares the `model` pane and passes `--choose`, and
  `src/main.rs` ignores the flag. Whether the offer is interactive in that pane,
  whether an unconfigured take triggers it or only reports it, and what the
  chooser writes when the person picks — configuration, a file on disk, or both
  — are unanswered.
- **Decoding: greedy or more.** The run brief says greedy is enough to start and
  that beam search is not to be built unless this design decides it is needed.
  Design states which, with the reason, and — because the bias string exists and
  `docs/evidence.md` shows it is what restores technical terms — whether and how
  `bias` reaches the decoder as an initial prompt at all. `Engine::transcribe`
  already receives it; an engine that accepts it and drops it would be a
  regression against what #26 was built for.
- **Whether the model loads at daemon start or on first take.** `resolve` runs at
  start (`src/daemon.rs:517`) and returns a built engine; a multi-gigabyte load
  there changes how long a daemon takes to become useful, and doing it lazily
  changes where its failure is reported. Both are consistent with the existing
  code; they are not the same behaviour.

## acceptance criteria

- **AC-1.** With `[stt] engine = "candle"` and a verified model present, a
  finished take is transcribed by code inside this binary: no child process is
  spawned for recognition and no network request is made on the take path.
- **AC-2.** The transcript reaches the take path through the existing
  `stt::Engine` trait unchanged — `transcribe(&self, audio: &Path, bias: &str)`
  — so `daemon::transcribe` (`src/daemon.rs:315`) needs no new branch for this
  engine, and the rewrite, context and delivery stages are untouched.
- **AC-3.** The engine reads the 16 kHz mono 16-bit PCM WAV that
  `audio::wav::write` produces, and refuses any other shape with a message that
  names what it found and what it expected.
- **AC-4.** A model chooser exists and can be run: it lists the offered models
  with each one's size before anything is downloaded, and downloads only the one
  chosen. Running it is `herdr-voice model` (with `--choose` as the manifest's
  pane already passes it), which no longer exits 69. The two tests that pin the
  unbuilt state follow —
  `the_commands_this_issue_implements_are_not_in_the_unimplemented_arm`
  (`src/main.rs:211-215`) and `the_usage_text_names_every_implemented_command`
  (`src/main.rs:228-233`), whose `USAGE` text does not name `model` — and are
  updated with it.
- **AC-5.** A downloaded model is verified before it is ever loaded, by an exact
  file name and by an integrity check strong enough to name a truncated download
  as one. None of the four checks `stt::model::locate` makes today is removed or
  weakened for the engine it already serves; the existing tests in
  `src/stt/model.rs` continue to pass unchanged.
- **AC-6.** A download interrupted part-way does not leave a file that a later
  run mistakes for a complete model — verifiable by truncating a file in the
  models directory and observing a named refusal rather than a load-time failure.
- **AC-7.** `[stt] model` selects which model this engine loads, and `[stt]
  language` is honoured, including `"auto"`, with the meaning #13 gave them
  (`docs/decisions.md`, 2026-08-25, #13: "`language = \"auto\"` … is what these
  programs already take to mean 'detect it'").
- **AC-8.** Every failure this engine can produce — no model, a model that fails
  verification, a download that could not start or could not finish, an
  unsupported compute device, a model file that does not match the configured
  identifier — is a message naming what to do next, returned through
  `EngineError` or the chooser's own output. No path added by this issue panics,
  unwraps a fallible value, or exits the daemon.
- **AC-9.** `cargo test` passes on a machine with no model file in the models
  directory, no network reachable, and no GPU — every test that needs weights,
  a tokenizer or a download uses a fake or a fixture. Verified by running the
  suite with the models directory absent and the network blocked, not by
  inspection.
- **AC-10.** `doctor` reports the built-in engine's real state: with
  `engine = "candle"` the model line is no longer `not used by this
  configuration` but the actual state of the model that engine would load —
  present, missing, or failing verification, each naming what to do next. The
  test that pins the opposite (`the_model_line_is_not_used_when_the_engine_is_not_built`,
  `src/doctor.rs:509-522`) is updated to the new truth, not deleted.
- **AC-11.** `stt::resolve_with`'s `"candle"` arm no longer returns
  `EngineError::NotBuilt`, and the test that asserts it does
  (`the_unbuilt_engines_say_so_and_name_the_one_that_works`, `src/stt.rs:204-219`)
  is updated to cover only the engines that are still unbuilt in this branch.

  > **Went further, 2026-09-10.** After merging #16, which built the `http`
  > engine, no engine is unbuilt and nothing constructed `EngineError::NotBuilt`
  > at all. The variant is deleted rather than narrowed, and a test asserts that
  > none of the three engines reports itself unbuilt.
- **AC-12.** `README.md:47-49` no longer says recognition needs an external
  engine, and `docs/design.md` §9's open question 2 (candle versus whisper.cpp)
  is left standing, since #2 is where it closes.
- **AC-13.** The choices reserved for the owner — the model list with its sizes,
  and the download source — are recorded in `docs/decisions.md` in the four-part
  form every row there uses, marked provisional and renameable, with the same
  wording standard `[stt] command` was given.
- **AC-14.** One real take is transcribed by the built-in engine on macOS, by
  hand, and written into `docs/evidence.md` with the platform, the model, and how
  long it took — the same way "Recognition, by hand on macOS" records the
  `whisper-cli` run. A negative result, recorded, satisfies this; a claim with no
  command and no output beside it does not (`CLAUDE.md`, S5).

## Out of scope / noticed, not turned into a criterion

- **The comparison with whisper.cpp itself.** Issue #2. The design must leave it
  possible — the same take, the same model identifier, a time that can be put
  beside the 1.65 s in `docs/evidence.md` — but running it is not this issue.
  AC-14 asks for one measurement of this engine, not for a comparison.
- **Issue #16's `http` engine.** In progress in a sibling worktree, touching the
  same `resolve_with` match and the same `doctor` function. Named in the run
  brief as a rebase to expect at merge time, not as work here.
- **Tagging a release, and building the distribution archives** that
  `docs/decisions.md` said would wait for this engine. Ending the reason for the
  hold is this issue; tagging is not.
- **The hallucinated-text problem** `docs/evidence.md` records (a minute of room
  tone producing "Продолжение следует..." four times). It is a property of
  Whisper, not of this engine, and the evidence section already says "Nothing is
  changed here yet".
- **The `mic` and `status` panes**, still at exit 69. Only `model` is in this
  issue's path.
- **Windows and Linux.** "macOS first," and `docs/design.md` §9 tracks Windows
  as a separate issue. Nothing here may branch on platform inside the binary
  where the manifest can express it (`CLAUDE.md`), but no platform beyond macOS
  is verified by this issue.
- **A permanently open capture stream** (`docs/design.md` §9, open question 4).
  Unrelated; recognition is downstream of capture.

## Risk

No `Risk` field exists to read: the trigger is a GitHub issue, not an ADO ticket
(`CLAUDE.md`, "Trigger and run root"). The issue has no comments as of
2026-09-09.

Noted rather than scored: this issue adds the first machine-learning dependency
stack to a crate whose entire dependency list is six crates, and the run brief
calls it the largest issue this repository has taken on. Build time, binary size
and the number of transitive dependencies are things design should state a
number for, because `docs/decisions.md` (2026-08-24, #3) already establishes that
this repository decides dependencies deliberately and writes down why.
