# AC_27

Acceptance criteria for issue #27, read from GitHub and checked against `main` at
`3dd45b8`.

## As is

`doctor` prints one line for the speech engine, built in `engine_finding_from`
(`src/doctor.rs:235`). For `candle` the line names what was verified (`"candle" is
ready, running <device>`). For every other engine that passes `stt::check_with`, the
`Ok(_)` arm prints `format!("{:?} is ready", stt.engine)`, for example
`engine ok "command" is ready`.

What `check_with` establishes (`src/stt.rs:149`):
- `command`: `[stt] command` is not empty, and when the list has `{model}`, the model
  resolves. Nothing about the program: whether it exists, is on `PATH`, or runs.
- `http`: `[stt] url` is not empty. Nothing about the endpoint.

A missing program is found when a take runs, and the failure names the `PATH` searched
(`src/stt/command.rs:91`). The daemon defers that check on purpose.

The quoted token is the engine kind, not a program name, but reads as one.

No test asserts the old text: tests on the engine line check `State::Ok` only
(`src/doctor.rs`, `the_engine_line_names_what_resolve_reports_for_each_engine`,
`the_model_is_located_once_per_doctor_run`).

## To be

1. For `command`, the engine line says what was established (`[stt] command` is set) and
   what was not (the program is not looked for until a take starts).
2. For `http`, the engine line says what was established (`[stt] url` is set) and what
   was not (the endpoint is not contacted until a take starts).
3. Neither line quotes the engine kind as if it were a program name, and neither says
   "ready".
4. The state of both lines stays `ok`; the exit code of `doctor` does not change.
5. The `candle` line, and every `missing` line (empty command, empty url, unknown engine,
   model not found), are unchanged.
6. The exact text is the one the orchestrator approves before S4; S2 records it.

## Requirements

- R1. A test per engine pins the new text (`command`, `http`).
- R2. A test pins that the `command` and `http` lines contain no `is ready` and do not
  quote the engine kind.
- R3. A test with a program that does not exist on `PATH` shows the line is still `ok`
  and does not claim the program was found (the line is true without a check).
- R4. The `candle` line test and the `missing` tests keep passing unchanged.
- R5. S5: `doctor` run from the built binary with `[stt] engine = "command"` and a
  program that is not on `PATH`, and with a program that is, prints the new line in both
  cases; recorded in `docs/evidence.md` with the platform.

## Out of bounds

- Checking the configured program, or running it, at `doctor` time: `[stt] command` is
  an argument list whose first element is often a shell, and running an arbitrary
  program with `--version` can hang.
- The `candle` line and the `missing` lines.
- Issues #21 and #22.
- Records in `docs/evidence.md` of earlier runs that quote the old line; they are what
  those runs printed.
