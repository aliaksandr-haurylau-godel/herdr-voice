# AC_26

## as-is

`Engine::transcribe(&self, audio: &Path) -> Result<String, EngineError>` is the
whole trait (`src/stt.rs:16-17`). It takes only the audio path; nothing about a
bias string reaches it, by construction.

`CommandEngine` (`src/stt/command.rs:36-40`) is built once at daemon start, in
`stt::resolve_with` (`src/stt.rs:105-135`), from the configuration read at that
time: the argument list, the model path and the language are all baked in at
construction. `command::render` (`src/stt/command.rs:15-34`) substitutes
`{audio}`, `{model}` and `{language}` by name in that argument list, and
appends the audio path when the list names no `{audio}` placeholder — the only
one of the three that is guaranteed to reach the program regardless of how the
list is written.

`daemon::dictate` (`src/daemon.rs:151-166`) calls `take_bias(...)` when a take
finishes, then `transcribe(runtime, &take)`. `take_bias`'s return value — a
`bias::Collected` whose `.bias` field is the finished, capped string
(`src/bias.rs:29-31`) — is discarded; the call has no binding
(`src/daemon.rs:159-164`). `daemon::transcribe` (`src/daemon.rs:303-320`) reads
`runtime.recognition` and calls `engine.transcribe(&take.path)` — no bias
string is passed in, because there is nowhere on the trait to pass it.

The only two engines that exist are `command` (built) and `candle`/`http`
(refused with `EngineError::NotBuilt`, naming issues #15 and #16 — neither is
built, so neither has an opinion on whatever shape this issue picks).

The measurement this issue exists to act on is in `docs/evidence.md`, section
"Recognition, by hand on macOS": one 70-second take of Russian speech with one
English term returned "пули квест" with no bias prompt, and "pull request"
with the same terms passed through `--prompt`, `-l ru` both times. Recognition
cost 1.5-1.8 seconds either way.

`whisper.cpp` (the program behind the `command` engine in every measurement
taken so far) holds roughly 224 tokens of prompt context. Issue #21 caps the
collected bias string at `[context] prompt_chars`, 600 characters by default
(`src/config.rs`, `Context::default`).

## to-be

The bias string `bias::collect` assembles for a take reaches the transcriber
for that same take, through whichever engine is configured, and — for the
`command` engine specifically — through a `{prompt}` placeholder a person can
name in `[stt] command` the same way `{audio}`, `{model}` and `{language}` are
named today. A spoken take containing an English term inside Russian speech,
run with the bias string wired in, returns that term rather than a Russian
near-homophone of it — verified by running it, not only by a test — and the
platform and the transcript are recorded in `docs/evidence.md` next to the
"пули квест" measurement this issue answers.

## requirements

Taken from the issue body directly:

1. "The bias string that issue #21 collects reaches the transcriber" — the
   collected string, not a copy or a summary of it, must be what the engine
   receives.
2. "An English term spoken inside Russian speech comes back as the term.
   Verified by a spoken take, not by a test alone." — a live measurement, not
   an assertion in a unit test, closes this issue.
3. "`Engine::transcribe` ... has no parameter for a bias string. ... So the
   trait widens, or the string arrives some other way." — the issue states
   this as the open question this issue must settle, not as a requirement to
   widen the trait specifically. Which of the two the design does is a design
   decision, out of this stage's scope.
4. "Whatever shape is chosen binds the two engines that are not built yet" —
   a requirement to choose the shape with those two engines in mind, not a
   requirement to build them (explicitly out of bounds, below).
5. "A `{prompt}` placeholder beside them is the obvious candidate ... a
   configured list that names no placeholder for it must still work." — for
   the `command` engine specifically: `{prompt}` substitution is expected, and
   the absence of that placeholder in a person's configured argument list must
   not break rendering or the take.
6. "`whisper.cpp` holds roughly 224 tokens there, and #21 caps the string at
   600 characters, so nothing here needs to cap it again." — no additional
   truncation of the bias string is part of this issue.

Implied, not asked for outright, and not turned into a criterion beyond what
is written above: nothing about the pane-title, branch or agent-kind
components `docs/design.md` still lists as out of #21's scope — this issue
inherits that scope boundary rather than reopening it.

## acceptance criteria

- **AC-1.** A take whose bias string is non-empty results in that string
  reaching the engine that transcribes the take — for the `command` engine,
  observable as the rendered argument list containing the string's text at the
  point a `{prompt}` placeholder appears in `[stt] command`.
- **AC-2.** `command::render` substitutes `{prompt}` in the configured argument
  list the same way it already substitutes `{audio}`, `{model}` and
  `{language}`: by name, wherever it appears, however many times it appears.
- **AC-3.** A configured `[stt] command` list containing no `{prompt}`
  placeholder still renders and still lets the take complete; the bias string
  is not force-appended the way the audio path is when `{audio}` is absent.
  (Chosen reading of "must still work" — the issue does not ask for a forced
  append, and forcing an argument onto a list a person wrote without asking
  for it would be new behavior beyond what `{audio}`'s special case already
  justifies. Flagged for the design stage to revisit if it disagrees.)
- **AC-4.** An empty bias string (every source missed, or `[context]
  prompt_chars = 0`) still lets the take complete normally — the `command`
  engine is not required to special-case emptiness beyond what plain string
  substitution already does.
- **AC-5.** No component in this issue caps, truncates or otherwise shortens
  the bias string a second time; the cap AC-5 of `tasks/21/AC_21.md`
  established is the only one.
- **AC-6.** A person can still configure `[stt] command` exactly as documented
  before this issue, without a `{prompt}` placeholder, and observe no change
  in behavior — adding the placeholder is opt-in.
- **AC-7.** A spoken take of Russian speech containing at least one English
  technical term, run with this issue's change in place and the same
  configuration as the "пули квест" measurement in `docs/evidence.md`,
  returns that term rather than a Russian near-homophone of it. Recorded in
  `docs/evidence.md`, naming the platform, the spoken phrase, and the returned
  transcript, next to the existing "Recognition, by hand on macOS" section —
  the same way that measurement was recorded. This criterion needs a person at
  a microphone; no test discharges it.
- **AC-8.** `EngineError`'s existing failure paths are unchanged in what they
  report: an engine that cannot run, or that produces nothing, still names
  what to do next (`CLAUDE.md`, "Rules for the code" — no new silent
  failure is introduced by widening the transcription path).

## Out of scope / noticed, not turned into a criterion

- Building `candle` (#15) or the endpoint engine (#16). The issue says so
  explicitly; this issue only fixes the shape they will have to satisfy.
- The rewrite stage. The issue says so explicitly.
- Collecting the bias string, or anything about `bias::collect` itself. That
  is #21, already merged; this issue only consumes what it produces.
- Adding branch, pane title or agent-kind components to the bias string.
  `docs/design.md` already states these are not collected, and nothing in
  this issue's body asks for them.
- A second, independent cap on the bias string beyond `[context]
  prompt_chars`. The issue states plainly that nothing here needs one.
