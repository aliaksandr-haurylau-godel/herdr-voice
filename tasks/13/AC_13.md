# AC_13 — recognition

Input: GitHub issue 13, `gh issue view 13`, no comments. `docs/design.md` section 4
(transcription) and section 7 (configuration), `docs/evidence.md`, the prototype in
`spike/`.

## as-is

A take already exists and is already clean. `src/capture.rs` produces
`Take { path, level_dbfs, target }`: a 16 kHz mono 16-bit WAV, refused before it
gets this far if its mean volume fell below `[audio] silence_db`. The path is
reported to the caller by `dictate`'s second invocation.

Nothing reads that file. `src/daemon.rs` answers `dictate` with the path and the
level and stops there; no module in the crate knows what a transcript is.

Configuration reads `[audio] input`, `[audio] silence_db`, `[stt] model`,
`[rewrite] engine` and `[rewrite] agent` (`src/config.rs`). There is no
`[stt] engine` and no `[stt] language`, although `docs/design.md` section 7 names
both.

`doctor` reports on a model with a contract issue 3 admitted was weak: a model
counts as present when a filename **contains** the configured value
(`src/doctor.rs`, `model_finding`). `docs/decisions.md` records that the
recognition stage has to replace it.

**What exists on the development machine, checked rather than assumed.**
`whisper-cli` is installed at `/opt/homebrew/bin/whisper-cli`. The model the
prototype used is on disk: `ggml-large-v3-turbo.bin`, 1.5 GB, in the owner's home
directory since April. The prototype invoked it as
`whisper-cli -m <model> -f <wav> -l <lang> -np -nt --prompt <bias>`
(`spike/spike.sh:288`) and required it to exist before starting
(`spike/spike.sh:103`).

`docs/evidence.md` holds what that produced: two seconds for a transcript without
context, one second with a bias prompt, and a term that stayed wrong in both —
form improved, the term did not, and the repair belongs to the rewrite stage.

## to-be

A finished take becomes text. The daemon hands the take's file to a transcription
engine chosen by configuration, gets a transcript back, and keeps it in the run's
state. An engine that is not available says so by name, and a model that is
missing or damaged is named as such rather than discovered at load time.

## Requirements

Asked for by the issue:

- R1 A transcript is produced from the take's file.
- R2 More than one engine, behind one interface, chosen by configuration.
- R3 The model name and the spoken language are configuration, not code.
- R4 The model contract from issue 3 is replaced: exact name, and an integrity
  check on anything downloaded.

Implied, and in scope only as far as R1 to R4 need them:

- R5 `[stt] engine` and `[stt] language` join the configuration, with defaults.
- R6 Tests that need neither a model nor a microphone, which every stage so far has
  managed.
- R7 No panic paths; every failure names what to do next.

## Chosen readings

1. **Which engine is built here.** The issue names three: `candle`, `http` and
   `command`. This issue builds **`command` only**. `candle` is issue #15 and
   `http` is issue #16; both are declared, and asking for either says so and names
   the engine that works. The reason is the
   order of the whole plugin rather than a judgement about `candle`: the chain from
   key to text is the thing that has to exist, `command` reaches it with a binary
   and a model that are already on the machine, and `candle` is a machine-learning
   stack, a download with an integrity check, and inference — none of it on that
   path. **This is a scope cut and it is flagged, not hidden**: the built-in engine
   is the design's default and the thing that makes the plugin work with no
   external toolchain, so its absence changes what the plugin is until it lands.
   Its own issue is filed so it is not lost.
2. **What "a transcript reaching the run's state" means.** The daemon keeps it and
   reports it; putting it into a pane is delivery, which is another task. So
   `dictate`'s second invocation answers with the transcript rather than with a
   file path.
3. **What the integrity check covers.** Anything this plugin downloads. Nothing is
   downloaded in this issue, because neither `command` nor `http` fetches a model,
   so the check is specified and exercised against a file this issue writes rather
   than against a real download.

## Answers the gate asked for

**How the take, the model and the language reach an external program.** Not by
appending the path: `whisper-cli` takes the file behind `-f` and needs `-m` and
`-l` as well (`spike/spike.sh:288`). The command is a configured argument list with
placeholders — `{audio}`, `{model}`, `{language}` — each replaced before the
program runs, and a list with no `{audio}` gets the path appended so a simple
program still works. The key is `[stt] command`, an array of strings, defaulting to
empty.

**That key is a new user-visible name and is flagged as the owner's**, like the
scope cut: `docs/design.md` section 7 defines `[stt]` without it, and the design
implies a configurable program without naming the key. It is recorded in
`docs/decisions.md` for confirmation rather than treated as settled.

**What `[stt] model` names.** An identifier, not a file name. The file is
`ggml-<model>.bin` in the models directory, which is both the convention these
models ship under and what is actually on the development machine —
`ggml-large-v3-turbo.bin` for the default `large-v3-turbo`. An exact-name rule
against the identifier alone could never match, which is what the reviewer caught.

**What the integrity check compares against.** Three things this plugin can check
without a download having happened: the file exists under exactly that name; it is
not implausibly small; and it begins with the four bytes `6C 6D 67 67`, the `ggml`
magic — read off the model on disk rather than assumed. A truncated or half-written
download fails the last two. When a `.sha256` sidecar sits beside the model, its
digest is checked too; issue #15, which downloads, writes that sidecar, and until
then its absence is not a failure.

**Three engines, not four.** AC-8 said four and was wrong: `candle`, `http` and
`command` are the whole set. Transcription has no `off` — a plugin that records and
then transcribes nothing has no purpose — and the test fake is not a configuration
value.

**The endpoint engine leaves this issue.** The second review asked which key holds
the endpoint and what the request and the answer look like. Both are user-visible
decisions of the same class as `[stt] command`, and answering them means inventing
a key, a default, whether a token and a model ride with it, what is posted and
where the transcript is read from — plus an HTTP client dependency. None of that is
on the path to a working chain, which the external command already reaches. `http`
becomes issue #16. This narrows the work again and it reduces the number of
user-visible names invented tonight rather than adding to it.

**What `auto` means to a command.** It is substituted like any other value, because
`auto` is what these programs already understand: `whisper-cli -l auto` asks the
model to detect the language. No argument is dropped and no rule about neighbouring
arguments exists — a person whose program needs the flag omitted omits it from their
own argument list, which is what a configured argument list is for.

## Acceptance criteria

- **AC-1** `[stt] engine` and `[stt] language` are read from the configuration,
  with defaults `"candle"` and `"auto"` as `docs/design.md` section 7 states, and
  an absent file leaves them there.
- **AC-2** One interface produces a transcript from a path, with one working
  implementation and a fake used by the tests. Adding the other two must not change
  the interface.
- **AC-3** With `engine = "command"`, the program in `[stt] command` is run with its
  placeholders replaced — `{audio}` by the take's path, `{model}` by the model file,
  `{language}` by the configured language — and what it prints on standard output
  becomes the transcript. A command with no `{audio}` placeholder gets the path
  appended.
- **AC-4** With `engine = "command"` and a program that is not on `PATH`, the
  failure names the program and what to set instead.
- **AC-5** With `engine = "command"` and a program that exits non-zero, the failure
  carries what the program printed on standard error, not only its exit code.
- **AC-6** With `engine = "http"`, the daemon answers that the endpoint engine is
  not built in this version and names the engine that is. Issue #16 builds it.
- **AC-7** With `engine = "candle"`, the daemon answers that the built-in engine is
  not built in this version and names the engine that is.
- **AC-8** An engine name that is none of the three is refused, listing the three.
- **AC-8a** An empty `[stt] command` under `engine = "command"` is refused, naming
  the key to set.
- **AC-9** A model is present only when `ggml-<model>.bin` exists in the models
  directory, for the `<model>` in the configuration. A file whose name merely
  contains it does not count, and `doctor` says the same thing the engine says.
- **AC-10** A model file that is empty, implausibly small, or does not begin with
  the `ggml` magic is reported as damaged, naming the file and what to do, rather
  than being handed to an engine. A `.sha256` sidecar, when present, is checked and
  a mismatch is reported the same way; its absence is not a failure.
- **AC-11** The second `dictate` answers with the transcript. A take that produced
  no text is reported as such rather than as an empty success.
- **AC-12** The language from the configuration reaches the program through the
  `{language}` placeholder, `"auto"` included: it is substituted like any other
  value, because it is the value these programs already take to mean "detect it".
- **AC-13** `doctor` reports the configured transcription engine the same way the
  daemon does: available, or not built with the engines that are named. The two must
  not be able to disagree, because somebody reading `doctor` is deciding what to do
  next.
- **AC-14** `README.md` states, in the section about installing, that recognition
  needs an external engine until the built-in one is built, and names what to set.
- **AC-15** Every test runs without a model, without a microphone and without a
  network. `cargo test --all`, `cargo clippy --all-targets -- -D warnings`,
  `cargo fmt --check` and `python3 scripts/check_manifest.py` pass, and the five CI
  checks pass.

## Out of scope / noticed

- The endpoint engine, and every name and wire format it needs — issue #16.
- The `candle` engine itself. Filed separately; `[stt] engine = "candle"` reports
  it is not built. The default stays `candle` on purpose: an engine that quietly
  becomes a different engine is worse than one that says it is missing, because the
  person who believes the built-in one is running finds out at the worst moment.
- Tagging a release. Not while the built-in engine is absent: a plugin installed by
  somebody else would need an external binary to hear anything, and avoiding exactly
  that is why the built-in engine is the design's default.
- Choosing a model from a list on first run, and downloading it. That belongs with
  `candle`, which is the engine that needs a downloaded model; `command` and `http`
  are pointed at something that already exists.
- Context, rewrite, delivery, indicator, push-to-talk.
- The bias prompt the prototype passed to `whisper-cli` (`--prompt`) is context,
  and context is its own task. This issue passes no prompt, which
  `docs/evidence.md` says costs punctuation and capitalisation but not terms.
- Deleting a take after it has been transcribed. Nothing deletes takes yet.
