# Decisions

Everything decided without the repository's owner. One line each, with the reason
it was decided that way and where it happened, so any of it can be read in one
sitting and any of it can be reversed.

Each entry also lives in the `RUN_<issue>.md` of the run that took it, in context.
This file is the list; the run file is the story.

| Decision | Basis | Where |
|---|---|---|
| The stage reviewers are project agents in `.claude/agents/`, not additions to anyone's global agent set | A project agent travels with the repository and is reviewed in the pull request like any other file; the alternative changes a personal environment that has nothing to do with this repository | 2026-08-24, #3 |
| `serde`, `serde_json` and `toml` are allowed; asynchronous runtimes are not, until a task appears that cannot be done without one | A hand-written JSON reader is a defect factory on escapes, unicode and nesting, and one such defect costs more than a line in `Cargo.toml`. A runtime, by contrast, buys nothing for a process that answers a few bytes for one person | 2026-08-24, #3 |
| `interprocess` is the only transport crate, and it is visible in `src/transport.rs` alone | `std` has a Unix socket and no Windows named pipe. Confining it means replacing it later is a change to one file | 2026-08-24, #3 |
| The machine-wide Windows pipe name is issue #6, not part of #3 | It is a real collision between two users on one machine, and it belongs neither to the frame nor to #1, which is about auto-repeat and audio capture | 2026-08-24, #3 |
| The daemon connects before it listens | It is the only order that tells a live daemon from a dead one's leftovers; reclaiming the name first would take it from a running process | 2026-08-24, #3 |
| There is no user-visible command to stop the daemon; `stop` exists only as a wire request the tests send | A new command is a new user-visible name, and names are the owner's decision. The tests needed a way to shut a listener down without signals; a person can use a signal | 2026-08-24, #3 |
| The frame is a header line plus the context bytes copied without inspection; the client parses nothing | Holding a key starts the client about twelve times a second, and it has no use for the fields. The daemon is resident and parses instead | 2026-08-24, #3 |
| The entrypoint travels as a fourth header token, with `-` for a variable that was not set | The daemon must name the entrypoint in what it records, and the variable reaches the client only. herdr does not set it for an action invoked from the command line, so the dash is the common case there | 2026-08-24, #3 |
| The configuration file is `config.toml` in `HERDR_PLUGIN_CONFIG_DIR`, or the same directory herdr computes without it | `herdr plugin config-dir` prints that directory even for a plugin that is not installed, which is the case `doctor` meets from a plain terminal | 2026-08-24, #3 |
| The minimum herdr version is a constant in the code, checked against the manifest by `scripts/check_manifest.py` | Two copies of one number drift. The check was verified by making them disagree | 2026-08-24, #3 |
| A speech model lives in `<state>/models/` and counts as present when a filename contains the configured model name | Enough for a report that says "no model"; not enough to choose what to load, which the recognition task has to strengthen with an exact name and an integrity check | 2026-08-24, #3 |
| `agent = "auto"` resolves against a candidate list of exactly one name, `claude` | It is the only agent command-line tool the prototype used and the only one every rewrite measurement was made with. A second name goes on the list when a second tool is measured | 2026-08-24, #3 |
| A peer that connects and closes without sending is a liveness probe, not a broken request, and the daemon stays quiet about it | `doctor` and a second `daemon` start both do exactly that. Three alarming lines sat in a log that had answered two real requests | 2026-08-24, #3 |
| The transport platform is chosen by `cfg(windows)`, never by `GenericNamespaced::is_supported()` | That predicate is true on macOS too, where a namespaced name resolves to a file under the temporary directory instead of the state directory | 2026-08-24, #3 |
| CI caps the test job at ten minutes, runs single-threaded uncaptured tests on Windows only, and cancels superseded runs | A deadlocking test otherwise sits for six hours and says nothing about which test it was; the diagnostic slows the platforms that do not need it; and two runs per push competed for runners, making a cancelled run indistinguishable from a failure | 2026-08-24, #3 |
| A pull request lands as one squashed commit | It is how #5 landed, and the history reads as one entry per piece of work | 2026-08-24, #3 |
| The client waits two seconds for a reply, on another thread | A daemon answering a few bytes has no reason to take longer, and a hang is the failure the bound exists to prevent | 2026-08-24, #3 |
| A take is driven by the `dictate` action the manifest already declares, not by a new subcommand | The issue asked for "a plain subcommand", which would be a new user-visible name — the owner's decision, not this stage's | 2026-08-25, #8 |
| Device selection stays by name, although `cpal` 0.18 offers a stable device identifier | The identifier addresses exactly the failure the name rule was written against, but the rule lives in `CLAUDE.md` and changing it belongs to whoever owns that file | 2026-08-25, #8 |
| The recorder owns a thread for the daemon's whole life, and the audio stream lives only there | A take spans two `dictate` invocations arriving on different connections and different threads, so the stream cannot live in a connection handler; and whether a `cpal` stream may move between threads is not stated plainly per platform, so this makes the question moot | 2026-08-25, #8 |
| The device is opened at 32, 48, 64 or 96 kHz — an integer multiple of 16 000 — preferring 48; a device offering only 44.1 kHz is refused by name | It turns a rational resampler into a filter and a stride, a few dozen testable lines instead of a dependency. It costs nothing on the hardware looked at, and where it costs something it says so rather than producing aliased audio quietly | 2026-08-25, #8 |
| A windowed-sinc low-pass at 7.5 kHz runs before decimation | Without it everything above 8 kHz folds back into the band, and that noise goes straight into recognition. Dropping samples unfiltered is not a conversion, it is a corruption | 2026-08-25, #8 |
| A configured device name that matches nothing is an error listing the names that exist, never a fall back to the default | The failure the name rule was written against is silent: the recording goes elsewhere and nothing says so | 2026-08-25, #8 |
| A refused take has its file removed, and the refusal names the device and the measured level | "Nothing happened" is unactionable; "you are recording from the wrong input, it measured −91 dB" is | 2026-08-25, #8 |
| The recorder's source of samples delivers two events, a block of samples or a failure, in both the real and the fake implementation | A device that goes away mid-take must be testable without a microphone, like everything else; an interface that cannot carry a failure makes that impossible | 2026-08-25, #8 |
| A take whose device fails ends at the failure; the partial audio is discarded and the reason is reported at the next `dictate` | A take that lost its device halfway is the same class of input as one from the wrong device, and sending it on produces a confident transcript of nothing. The next `dictate` is the first moment there is anywhere to report to, since the indicator does not exist yet | 2026-08-25, #8 |
| The configuration is read once at daemon start and handed to the recorder thread | Re-reading per take would let the input device change without a restart, which nothing asks for, and would put file system access on the path that runs while somebody is speaking | 2026-08-25, #8 |
| The check workflow installs the ALSA development headers on `ubuntu-latest` | `cpal` pulls `alsa-sys` on Linux, and without the headers nothing builds there at all — not the tests, not clippy, not the format check | 2026-08-25, #8 |
| The Linux verification was run in a container, not prepared as a script for later | Corrects a wrong basis of mine: I reported that no container engine existed, having enumerated docker, podman, colima, nerdctl and lima and none other. Apple's `container` 1.1.0 is installed and running on this machine, so the check could happen immediately. The `sandbox` skill itself is a user-interface command and cannot be invoked from an agent, so the runtime was driven directly and nothing was installed on the host | 2026-08-25, #9 |
| A `dictate` that reports a remembered device failure only reports and clears it; the take starts on the invocation after that | Reporting and starting at once would hide the failure behind a recording the person did not know had begun | 2026-08-25, #8 |
| The reply for an accepted take carries the file path and the measured level, not the path alone | The criterion asks for the level to be reported, not only used to refuse; and a level next to an accepted take is what makes a marginal input visible before it becomes a bad transcript | 2026-08-25, #8 |
| One worktree per line of work; two agents never share a checkout | A branch switch in a shared working directory makes the other line's files vanish mid-edit. It happened twice within an hour, from both sides. Read other branches with `git show`, not by checking them out | 2026-08-25, #8 |
| `dictate` stays in `needs_target_pane`: the target pane is pinned when a take begins and held until delivery, and a take does not start when no pane can be determined | Not only delivery needs the pane. The indicator is drawn on a specific pane from the moment recording starts, and a target chosen at the end follows the focus while the person is still speaking — they look at one agent, and the text goes to whichever they switched to while thinking. Losing a take is worse than nothing and better than delivering it to the wrong agent; the prototype pinned the target at the start for this reason | 2026-08-25, #8 |
| A refused take names microphone permission among the things to check | On macOS a denied permission delivers silence rather than an error, so it is indistinguishable from a muted or wrong input from inside the process | 2026-08-25, #8 |
| The client prints what the daemon says on success, to standard output, and failures to standard error | A take that worked was otherwise indistinguishable from one that did nothing: the daemon answered with the path and the level and the client threw it away | 2026-08-25, #8 |
| The Linux check was run now, in a container on the development machine, instead of being handed to the owner as a script to run later | Apple `container` is installed and running there, so a throwaway Debian container was available without installing anything; a result costs the owner nothing to read, and a script left unrun establishes nothing | 2026-08-25, #9 |
| The check is one script, `scripts/linux-check.sh`, that installs its own prerequisites and prints a step table | The value of the exercise is that it can be repeated after issue #8 lands capture and on a machine that is not this one; a sequence of commands typed by hand is not repeatable and its result is not comparable | 2026-08-25, #9 |
| A capture-facing command that exits 69, "not implemented yet", is recorded as pending and never as a pass | The point of a container with no sound hardware is the device-absence behaviour, and it does not exist yet. A step that goes green on "not built" would go green forever | 2026-08-25, #9 |
| The `no-device` step drives a take through the `dictate` action and judges the record herdr keeps, not the exit code of `herdr plugin action invoke` | That command returns 0 for "the action was started"; the plugin's own exit code, standard output and standard error appear only in `herdr plugin log list`. Reading that record is also what detects a hang: a take that never ends leaves the record in `running` | 2026-08-25, #9 |
| The check creates a workspace so that herdr names a focused pane | `dictate` delivers into a pane and refuses to start without one, so a server with no workspace can only ever answer "the invocation context names no focused pane" — which says nothing about audio | 2026-08-25, #9 |
| `jq` is a prerequisite of the check, installed with the other packages | The assertions are about named fields in herdr's JSON records. Grepping the raw text for `"status":"succeeded"` already produced one false failure, on a `cancel` that had succeeded and was still being written | 2026-08-25, #9 |
| The check waits for a plugin-log record to leave `running` instead of reading it the moment the action returns | herdr writes the record when the command ends, not when it starts | 2026-08-25, #9 |
| The check's cleanup kills every `herdr-voice daemon` it can find, not only one it started itself | A daemon herdr had started from the manifest's `[[startup]]` entry outlived the server that spawned it, and the next run connected to a process on its way out: `doctor` said `daemon ok` and the take that followed got a closed connection | 2026-08-25, #9 |
| A `named-device` step was added, exercising `[audio] input` set to a name no device has | It is the branch that decides where a recording comes from, and a wrong answer there records from the wrong input in silence. It had been checked by hand on macOS only | 2026-08-25, #9 |
| `HERDR_VOICE_REVISION` names the revision when the checkout is not a git one | A worktree mounted into a container keeps its `.git` outside the mount, so `git rev-parse` cannot answer and the report loses the revision it exists to carry | 2026-08-25, #9 |
| The `no-device` step was run against an action that exits 69 before its result was recorded as a pass | A step whose failure path has never executed is not evidence. Judging `ptt`, which answers "not implemented yet", made the step fail with `the take reported 'not implemented yet'` | 2026-08-25, #9 |
| **A scope cut, and it needs the owner's word: the built-in `candle` engine is deferred to #15.** #13 builds the external-command and endpoint engines only | The chain from keypress to text is what has to exist, and an already-installed `whisper-cli` with a model already on disk reaches it tonight; `candle` is a machine-learning stack, a verified download and inference, none of it on that path. But the owner asked for a plugin that needs nothing else installed, and that request is why the built-in engine is the design's default — so this cut changes what the plugin is until #15 lands, and it is his to confirm or reverse | 2026-08-25, #13 |
| No release is tagged while the built-in engine is absent | A plugin installed by somebody else would need an external binary to hear anything, which is exactly what the built-in engine exists to avoid. Tonight's goal is a working chain on one machine, not distribution | 2026-08-25, #13 |
| The default engine stays `candle`, and an unbuilt engine says so rather than falling back to a working one | Somebody who believes the built-in engine is running, while an external one actually is, finds out at the worst possible moment. A missing engine that names itself is better than a silent substitution | 2026-08-25, #13 |
| `README.md` states that recognition needs an external engine until the built-in one is built | A public repository must not promise what it does not contain | 2026-08-25, #13 |
| A model counts as present only on an exact file name, with an integrity check on anything downloaded | The substring test inherited from #3 matches an unrelated file, and a truncated download must fail by name rather than confusingly at load time | 2026-08-25, #13 |
| **A new configuration key, `[stt] command`, and it needs the owner's word**: an array of arguments with `{audio}`, `{model}` and `{language}` placeholders | `whisper-cli` takes the file behind `-f` and needs `-m` and `-l` too, so appending a path does not work for the one binary this rests on. `docs/design.md` section 7 defines `[stt]` without any key for a program, so the name is ours to propose and his to confirm — configuration keys are user-visible names | 2026-08-25, #13 |
| `[stt] model` is an identifier; the file is `ggml-<model>.bin` in the models directory | An exact-name rule against the identifier alone could never match: the default is `large-v3-turbo` and the file on disk is `ggml-large-v3-turbo.bin` | 2026-08-25, #13 |
| A model's integrity is its exact name, a plausible size, and the four leading bytes `6C 6D 67 67` — the `ggml` magic, read off the model on disk | It catches a truncated or half-written download without needing a digest nobody has yet. A `.sha256` sidecar is checked when present, and #15, which downloads, writes it | 2026-08-25, #13 |
| Transcription has no `off` engine: the set is exactly `candle`, `http`, `command` | A plugin that records and then transcribes nothing has no purpose. An earlier draft of the criteria said four engines and was wrong | 2026-08-25, #13 |
